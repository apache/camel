= Switch EIP
:doctitle: Switch
:shortname: switch
:description: Evaluates a selector once and dispatches to a fixed endpoint by literal scalar or composite values
:since: 4.23
:supportlevel: Stable
:tabs-sync-option:

*Since Camel {since}*

Switch selects one destination from a table declared by the route author.
The selector can use any Camel expression language. Its result selects a case;
it cannot supply a new endpoint URI.

Use Switch for literal value dispatch. Use xref:choice-eip.adoc[Choice] for
predicates, ranges, overlapping conditions, or nested processing steps. A case can
send to a `direct:` route when more processing is needed. Use xref:toD-eip.adoc[To D]
when the endpoint URI itself must be calculated dynamically.

== Scalar selectors

The selector is evaluated once on each entry. Scalar results are converted to strings
and matched case-insensitively using the English locale. An empty string is a valid
literal. An asterisk is literal, not a wildcard. Duplicate normalized values are
rejected at startup.

[tabs]
====
Java::
+
[source,java]
----
from("direct:tickets")
    .doSwitch(header("department"))
        .doCase("billing", "direct:billing")
        .doCase("technical", "direct:technical")
        .otherwise("direct:review")
    .end();
----
XML::
+
[source,xml]
----
<switch otherwise="direct:review">
    <selector><header>department</header></selector>
    <case value="billing" uri="direct:billing"/>
    <case value="technical" uri="direct:technical"/>
</switch>
----
YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:tickets
      steps:
        - switch:
            selector:
              header:
                expression: department
            case:
              - value: billing
                uri: direct:billing
              - value: technical
                uri: direct:technical
            otherwise: direct:review
----
====

A null or unmatched result uses `otherwise`. Without `otherwise`, the exchange
continues after Switch. Selector failures follow normal Camel error handling and
never select the fallback. Streams are reset after selector evaluation when stream
caching is enabled. Loops and retries that enter Switch again evaluate the selector
again; results are not cached across entries.

== Composite selectors

Configure `keys` when the selector returns a map. Each case supplies every declared
key exactly once. All values must match. Key names are case-sensitive, while string
values are case-insensitive. Entry order is irrelevant and additional result fields
are ignored. Missing keys, null field values and unsupported value types are errors.
A null result map still uses the fallback.

Composite literals support strings, booleans and finite decimal numbers. These types
are distinct: string `"true"` does not match boolean `true`, and string `"2"` does not
match number `2`. Numbers compare by decimal value, so `2` and `2.0` match. Duplicate
combinations, including differences only in letter case or numeric scale, fail at
startup. Scalar `value` cases and composite `values` cases cannot be mixed.

[tabs]
====
Java::
+
[source,java]
----
from("direct:tickets")
    .doSwitch(header("decision"))
        .keys("department", "urgent")
        .doCase().value("department", "billing").value("urgent", true)
            .id("urgentBilling").to("direct:urgent-billing")
        .doCase().value("department", "billing").value("urgent", false)
            .to("direct:billing")
        .otherwise("direct:review")
    .end();
----
XML::
+
[source,xml]
----
<switch otherwise="direct:review">
    <selector><header>decision</header></selector>
    <keys>department</keys>
    <keys>urgent</keys>
    <case id="urgentBilling" uri="direct:urgent-billing">
        <values name="department" value="billing"/>
        <values name="urgent" type="boolean" value="true"/>
    </case>
    <case uri="direct:billing">
        <values name="department" value="billing"/>
        <values name="urgent" type="boolean" value="false"/>
    </case>
</switch>
----
YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:tickets
      steps:
        - switch:
            selector:
              header:
                expression: decision
            keys: [department, urgent]
            case:
              - id: urgentBilling
                values: [department: billing, urgent: true]
                uri: direct:urgent-billing
              - values: [department: billing, urgent: false]
                uri: direct:billing
            otherwise: direct:review
----
====

YAML `values` is a sequence of single-entry mappings. Quote strings that would
otherwise be read as booleans or numbers. XML literals default to `type="string"`;
use `type="boolean"` or `type="number"` explicitly. Keys select fields in the returned
map; they do not implicitly read separate message headers.

Cases are compiled into a lookup table. Constructing a composite key involves the
selected fields, but lookup does not scan the declared cases.

=== Semantic decisions

With `camel-semantic` and a provider configured, a named batch can be used directly:

[source,yaml]
----
- route:
    from:
      uri: direct:tickets
      steps:
        - switch:
            selector:
              language:
                language: semantic
                expression: refs:department,urgent
            keys: [department, urgent]
            case:
              - values: [department: billing, urgent: true]
                uri: direct:urgent-billing
              - values: [department: billing, urgent: false]
                uri: direct:billing
            otherwise: direct:review
----

Declare the questions using the xref:languages:semantic-language.adoc[Semantic language].
Batching, thresholds and uncertainty policies belong to that language and its provider.
Switch has no dependency on semantic evaluation. Store a result explicitly in a
variable, header or exchange property when it should be reused by later EIPs.

== Destinations and management

Case and fallback URIs support property placeholders resolved at startup. Simple
expressions in URIs are rejected. In YAML, a case also accepts `uri` plus `parameters`:

[source,yaml]
----
case:
  - value: orders
    uri: kafka
    parameters:
      topic: orders
----

Each case has an identity for tracing, debugging and management. The Switch MBean's
`extendedInformation` table reports case IDs, literal values, destination URIs and
selection counts. These counts indicate case selection, not successful delivery.
`UnmatchedCount` also records unmatched results when no fallback is configured.
