The FHIR component integrates with the
http://hapifhir.io/[HAPI-FHIR] library, which is an open-source implementation of the
http://hl7.org/implement/standards/fhir/[FHIR] (Fast Healthcare Interoperability Resources) specification in Java.

Maven users will need to add the following dependency to their pom.xml
for this component:


[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-fhir</artifactId>
    <version>${camel-version}</version>
</dependency>
----

== URI Format

The FHIR Component uses the following URI format:

----
fhir://endpoint-prefix/endpoint?[options]
----

Endpoint prefix can be one of:

* capabilities
* create
* delete
* history
* load-page
* meta
* operation
* patch
* read
* search
* transaction
* update
* validate

[NOTE]
====
This is an API-based component, so per-call parameters can be supplied through `Camel`-prefixed
exchange headers in addition to the endpoint options. If the route consumes messages from untrusted
producers, strip these internal headers at the trust boundary -- for example with
`removeHeaders("Camel*")` -- before the message reaches this component, so that a sender cannot
override the API call. See xref:manual::security-model.adoc[the Camel security model] for details.
====

== Usage

The URI names the API and its method, such as `fhir://read/resourceById`. The parameters of the method are endpoint options, or headers that start with `CamelFhir.`, such as `CamelFhir.stringId`. The routes below create a patient from JSON, read a patient by its id, and search patients by family name:

[source,yaml]
----
- route:
    from:
      uri: direct:createPatient
      steps:
        - to:
            uri: fhir://create/resource
            parameters:
              serverUrl: http://localhost:8080/fhir
              fhirVersion: R4
              inBody: resourceAsString
        - log:
            message: "Created ${body.id.value}"
- route:
    from:
      uri: direct:readPatient
      steps:
        - setHeader:
            name: CamelFhir.stringId
            expression:
              simple:
                expression: "${body}"
        - to:
            uri: fhir://read/resourceById
            parameters:
              serverUrl: http://localhost:8080/fhir
              fhirVersion: R4
              resourceClass: Patient
        - marshal:
            fhirJson:
              fhirVersion: R4
        - log:
            message: "${body}"
- route:
    from:
      uri: direct:searchPatients
      steps:
        - to:
            uri: fhir://search/searchByUrl
            parameters:
              serverUrl: http://localhost:8080/fhir
              fhirVersion: R4
              url: "Patient?family=Simpson"
        - log:
            message: "Found ${body.total} patients"
----

The `inBody` option names the parameter of the method that the message body is, such as `resourceAsString` in the
first route. The body is passed as it is, without type conversion, so a parameter of type String needs a String body:
convert a byte array or a stream with `convertBodyTo` first. Without `inBody` the body is not used.

After the call the message body is the result of the method: a `MethodOutcome` for create, update, patch, delete and
validate, and a HAPI FHIR model object for the others, such as the `Bundle` of a search or the resource of a read. Marshal
a resource or a `Bundle` with `fhirJson` or `fhirXml` to get text.
