The AWS Bedrock Agent component works with the ingestion jobs of the knowledge bases of the
https://aws.amazon.com/bedrock/[AWS Bedrock] service: an ingestion job syncs a data source into a knowledge base.
The producer starts, lists and gets ingestion jobs, and the consumer polls the state of one ingestion job.

Prerequisites

You must have a valid Amazon Web Services developer account, and be
signed up to use Amazon Bedrock. More information is available at
https://aws.amazon.com/bedrock/[Amazon Bedrock].

== Usage

=== Static credentials, Default Credential Provider and Profile Credentials Provider

You have the possibility of avoiding the usage of explicit static credentials by specifying the useDefaultCredentialsProvider option and set it to true.

The order of evaluation for Default Credentials Provider is the following:

 - Java system properties - `aws.accessKeyId` and `aws.secretKey`.
 - Environment variables - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
 - Web Identity Token from AWS STS.
 - The shared credentials and config files.
 - Amazon ECS container credentials - loaded from the Amazon ECS if the environment variable `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` is set.
 - Amazon EC2 Instance profile credentials. 

You have also the possibility of using Profile Credentials Provider, by specifying the useProfileCredentialsProvider option to true and profileCredentialsName to the profile name.

Only one of static, default and profile credentials could be used at the same time.

For more information about this you can look at https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html[AWS credentials documentation]

=== Bedrock Agent Producer operations

The producer supports the following operations, set with the `operation` option or the `CamelAwsBedrockAgentOperation` header:

- startIngestionJob: starts an ingestion job of the data source `dataSourceId` into the knowledge base `knowledgeBaseId`.
The body is set to the id of the new ingestion job.
- listIngestionJobs: lists the ingestion jobs of the data source `dataSourceId` of the knowledge base `knowledgeBaseId`.
The body is set to the list of `IngestionJobSummary` of the AWS SDK.
- getIngestionJob: gets the ingestion job `ingestionJobId` of the data source `dataSourceId` of the knowledge base `knowledgeBaseId`.
The body is set to the `IngestionJob` of the AWS SDK, the `CamelAwsBedrockAgentIngestionJobStatus` header to its status,
and the `CamelAwsBedrockAgentIngestionJobFailureReasons` header to its failure reasons, if it has any.

The knowledge base, data source and ingestion job ids are taken from the `knowledgeBaseId`, `dataSourceId` and
`ingestionJobId` options. The `CamelAwsBedrockAgentKnowledgeBaseId`, `CamelAwsBedrockAgentDataSourceId` and
`CamelAwsBedrockAgentIngestionJobId` headers are used only when the option is not set.

With `pojoRequest=true`, the body is the request of the AWS SDK instead (`StartIngestionJobRequest`,
`ListIngestionJobsRequest` or `GetIngestionJobRequest`), and the ids are taken from it.

=== Bedrock Agent Consumer

The consumer polls the ingestion job `ingestionJobId` of the data source `dataSourceId` of the knowledge base
`knowledgeBaseId`; the three options must be set. On every poll it sends an exchange with the `IngestionJob` of the AWS SDK
as the body and the `CamelAwsBedrockAgentIngestionJobStatus` and `CamelAwsBedrockAgentIngestionJobFailureReasons` headers,
as the getIngestionJob operation does. It does so on every poll, also when the job did not change since the previous poll,
so filter on the status to act once the job is done, and set the poll `delay` to how often the job should be checked.

=== Example

The following route starts an ingestion job, which syncs a data source into a knowledge base:

[source,yaml]
----
- route:
    from:
      uri: direct:ingest
      steps:
        - to:
            uri: aws-bedrock-agent:agent
            parameters:
              operation: startIngestionJob
              knowledgeBaseId: KB12345678
              dataSourceId: DS12345678
              region: us-east-1
              accessKey: "{{aws.access-key}}"
              secretKey: "{{aws.secret-key}}"
        - log:
            message: "${body}"
----

== Dependencies

Maven users will need to add the following dependency to their pom.xml.

*pom.xml*

[source,xml]
---------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-aws-bedrock</artifactId>
    <version>${camel-version}</version>
</dependency>
---------------------------------------

where `$\{camel-version}` must be replaced by the actual version of Camel.
