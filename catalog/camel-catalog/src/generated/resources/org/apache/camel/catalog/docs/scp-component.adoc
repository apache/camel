The Camel Jsch component supports the
http://en.wikipedia.org/wiki/Secure_copy[SCP protocol] using the Client
API of the http://www.jcraft.com/jsch/[Jsch] project. Jsch is already
used in camel by the xref:ftp-component.adoc[FTP] component for the *sftp:*
protocol.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-jsch</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

----
scp://host[:port]/destination[?options]
----

The file name can be specified either in the <path> part of the URI or
as a "CamelFileName" header on the message (`Exchange.FILE_NAME` if used
in code).

== Usage

The SCP component copies the message body to a file on the remote host.
In the following route, the file consumer sets the `CamelFileName` header,
and each file of a local folder is copied to the `/upload` directory of the host.
The host key is checked against a known hosts file:

[source,yaml]
----
- route:
    from:
      uri: file:outbox
      steps:
        - to:
            uri: scp://myhost:22/upload
            parameters:
              username: "{{scp.username}}"
              password: "{{scp.password}}"
              knownHostsFile: /home/camel/.ssh/known_hosts
              strictHostKeyChecking: "yes"
----

The directory of the endpoint (`/upload` above) must exist on the remote host, as scp does not create it:
when it does not exist, each file is written to a file named like the directory, and the last one wins.
The sub directories in the `CamelFileName` header (such as `mysub/hello.txt`) are created in that directory.

Without a known hosts file (`useUserKnownHostsFile=false` and no `knownHostsFile`), no host is known,
so the option `strictHostKeyChecking` decides: with `yes` the connection fails, with `no` (the default)
the host key is not checked.


== OpenSSH Certificate Authentication

Camel supports OpenSSH certificate-based authentication for SCP connections, where a user's public key is signed by a Certificate Authority (CA). This is configured using the `certFile`, `certUri`, or `certBytes` parameters alongside the private key:

[tabs]
====
Java::
+
[source,java]
----
to("scp://host/path?username=myuser"
   + "&privateKeyFile=/path/to/user_key"
   + "&certFile=/path/to/user_key-cert.pub");
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: file:outbox
      steps:
        - to:
            uri: scp://host/path
            parameters:
              username: myuser
              privateKeyFile: /path/to/user_key
              certFile: /path/to/user_key-cert.pub
----
====

See the xref:sftp-component.adoc[SFTP component] documentation for more details on certificate authentication options.

== Limitations

Currently, camel-jsch only supports a
https://www.javadoc.io/doc/org.apache.camel/camel-api/current/org/apache/camel/Producer.html[Producer]
(i.e., copy files to another host).
