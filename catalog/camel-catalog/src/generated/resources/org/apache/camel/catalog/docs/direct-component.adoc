= Direct Component
:doctitle: Direct
:shortname: direct
:artifactid: camel-direct
:description: Call another endpoint from the same Camel Context synchronously.
:since: 1.0
:supportlevel: Stable
:tabs-sync-option:
:component-header: Both producer and consumer are supported
:core:

*Since Camel {since}*

*{component-header}*

The Direct component provides direct, synchronous invocation of any
consumers when a producer sends a message exchange.
This endpoint can be used to connect existing routes in the *same*
camel context.

[TIP]
====
*Asynchronous*

The xref:seda-component.adoc[SEDA] component provides asynchronous invocation of
any consumers when a producer sends a message exchange.
====

== URI format

----
direct:someId[?options]
----

Where _someId_ can be any string to uniquely identify the endpoint.

== Usage

The route that consumes from a direct endpoint runs in the thread of the producer, and the producer continues with the
message as that route leaves it.
A direct endpoint is therefore called like a method: from Java code, call a route with `requestBody` of a
xref:manual::producertemplate.adoc[ProducerTemplate] to get its reply:

[source,java]
----
String reply = template.requestBody("direct:processOrder", order, String.class);
----

=== One route per endpoint

Only one route can consume from a direct endpoint.
A second route that consumes from the same endpoint fails to start with
`Multiple consumers for the same endpoint is not allowed: direct://processOrder`.
To send a message to several routes, use the xref:eips:multicast-eip.adoc[Multicast] or
xref:eips:recipientList-eip.adoc[Recipient List] EIP, or the xref:seda-component.adoc[SEDA] component with
`multipleConsumers=true`.

=== When no route consumes from the endpoint

When no started route consumes from the endpoint, the producer waits up to `timeout` milliseconds (30 seconds by
default) for one to start, for example while Camel starts or reloads routes.
Then the exchange fails with `DirectConsumerNotAvailableException`.
Its message starts with `No consumers available on endpoint:`, and says which route consumes from the endpoint and its
status, or that no route does (with a close endpoint name when there is one), and how long the producer waited.

Set `block=false` to fail without waiting, or `failIfNoConsumers=false` to drop the message (logged at `DEBUG`) instead
of failing.

The common causes are:

* The route is not loaded. With Spring Boot, the `RouteBuilder` class must be a Spring bean, for example annotated with
  `@Component`. With Camel Quarkus, a `RouteBuilder` class from another jar is only found when that jar has a Jandex
  index. XML and YAML routes must be in the files Camel loads routes from.
* The producer and the route use a different name, for example because of a typo.
* The route is stopped or suspended, or it did not start because of `autoStartup=false`.
* The route is in another CamelContext: a direct endpoint only reaches the routes of its own CamelContext.
* With the xref:manual::rest-dsl.adoc[Rest DSL], a direct route that only one rest service calls is inlined into that
  service (the `inlineRoutes` option, enabled by default), so other routes cannot call it.

NOTE: A `ProducerTemplate` sends only once the CamelContext has started. Sending earlier, for example from a Spring
`@PostConstruct` method, fails with another exception, before any direct endpoint is called.

== Examples

In the route below, we use the direct component to link the two routes together:

[tabs]
====
Java::
+
[source,java]
----
from("activemq:queue:order.in")
    .to("bean:orderService?method=validate")
    .to("direct:processOrder");

from("direct:processOrder")
    .to("bean:orderService?method=process")
    .to("activemq:queue:order.out");
----

XML::
+
[source,xml]
----
<route>
 <from uri="activemq:queue:order.in"/>
 <to uri="bean:orderService?method=validate"/>
 <to uri="direct:processOrder"/>
</route>

<route>
 <from uri="direct:processOrder"/>
 <to uri="bean:orderService?method=process"/>
 <to uri="activemq:queue:order.out"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: activemq:queue:order.in
      steps:
        - to:
            uri: bean:orderService
            parameters:
              method: validate
        - to:
            uri: direct:processOrder
- route:
    from:
      uri: direct:processOrder
      steps:
        - to:
            uri: bean:orderService
            parameters:
              method: process
        - to:
            uri: activemq:queue:order.out
----

====

See also samples from the xref:seda-component.adoc[SEDA] component, how they can be used together.
