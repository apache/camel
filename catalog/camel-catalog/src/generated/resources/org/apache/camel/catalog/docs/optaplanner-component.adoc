*Since Camel {since}*

*{component-header}*

The http://www.optaplanner.org/[OptaPlanner] component solves the planning problem contained in a
message with http://www.optaplanner.org/[OptaPlanner].
For example, feed it an unsolved Vehicle Routing problem and it solves
it.

The component supports consumer listening for `SolverManager` results and
producer for processing Solution and ProblemChange.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
------------------------------------------------------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-optaplanner</artifactId>
    <version>x.x.x</version><!-- use the same version as your Camel core version -->
</dependency>
------------------------------------------------------------------------------------

== Message Body

Camel takes the planning problem from the message body, solves it and sets
the best solution as the message body. The body supports the following use cases:

* If the body is an instance of the `PlanningSolution` class of the solver configuration, then it
is solved, either synchronously or asynchronously. In both cases the exchange continues
with the best solution as the body.
* If the body is an instance of `ProblemChange`, then it is added to the problem being solved
with the same `problemId`, and the body is left unchanged.
* Any other body fails the exchange, as the solver cannot solve it.

The consumer receives an exchange each time a producer solving asynchronously, with the same
`problemId`, finds a new best solution. Its body is empty: the best solution is in the
`CamelOptaPlannerBestSolution` header.


=== Examples

Solve a planning problem on the ActiveMQ queue with OptaPlanner, passing the `SolverManager`:

[tabs]
====
Java::
+
[source,java]
----
from("activemq:My.Queue")
    .to("optaplanner:problemName?solverManager=#solverManager");
----

XML::
+
[source,xml]
----
<route>
  <from uri="activemq:My.Queue"/>
  <to uri="optaplanner:problemName?solverManager=#solverManager"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: activemq:My.Queue
      steps:
        - to:
            uri: optaplanner:problemName
            parameters:
              solverManager: "#solverManager"
----
====

Expose OptaPlanner as a REST service, passing the Solver configuration file:

[tabs]
====
Java::
+
[source,java]
----
from("cxfrs:bean:rsServer?bindingStyle=SimpleConsumer")
    .to("optaplanner:problemName?configFile=/org/foo/barSolverConfig.xml");
----

XML::
+
[source,xml]
----
<route>
  <from uri="cxfrs:bean:rsServer?bindingStyle=SimpleConsumer"/>
  <to uri="optaplanner:problemName?configFile=/org/foo/barSolverConfig.xml"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: cxfrs:bean:rsServer
      parameters:
        bindingStyle: SimpleConsumer
      steps:
        - to:
            uri: optaplanner:problemName
            parameters:
              configFile: /org/foo/barSolverConfig.xml
----
====
