*Since Camel {since}*

*{component-header}*

The Solr component allows you to interface with an
https://solr.apache.org/[Apache Solr] server.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-solr</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== Usage

=== Message Operations

The following Solr operations are currently supported. Set an
exchange header with a key of "operation" and a value set to one of
the following. Some operations also require the message body to be set.

* `INSERT`
* `DELETE`
* `SEARCH`
* `PING`

[width="100%",cols="10%,10%,80%",options="header",]
|=======================================================================
|Operation |Message body |Description

|`INSERT` | n/a |inserts/updates a document using message headers (solr fields must be prefixed with "CamelSolrField."), or with no such headers, sends only the solr parameters (such as a commit)
|`INSERT` | File |inserts/updates a document or documents using the given File (using ContentStreamUpdateRequest)
|`INSERT` | SolrInputDocument or Collection<SolrInputDocument>|inserts/updates a document or documents based on the given (collection of) SolrInputDocument
|`INSERT` | bean or Collection<bean> |inserts/updates a document or documents based on values in an http://wiki.apache.org/solr/Solrj#Directly_adding_POJOs_to_Solr[annotated bean]
|`INSERT` | Map or Collection<Map> |inserts/updates a document or documents with the fields of the Map
|`INSERT` | String |inserts/updates the documents of the given JSON or XML text: a JSON array of documents, or XML documents (an `<add>` element is added when the text does not start with one)

|`DELETE` | String or Collection<String> | delete a record by ID (or collection of ids), or by a query (or a collection of queries) when the header `CamelSolrDeleteByQuery` or the option `deleteByQuery` is true (false by default)
|`DELETE` | n/a | sends only the solr parameters (such as a commit)

|`PING` |n/a | Pings the solr instance

|`SEARCH` |SolrQuery | Performs a search request to the solr instance
|`SEARCH` |QueryRequest | Performs a search request to the solr instance
|`SEARCH` |String | Performs a search request with the body as the query
|`SEARCH` | n/a | Performs a search request with the query of the `CamelSolrQueryString` header (or the `CamelSolrParam.q` header)
|=======================================================================

When the message has no body and the headers do not give what the operation needs (the `CamelSolrField.` headers or
solr parameters for `INSERT`, solr parameters for `DELETE`, the `CamelSolrQueryString` header for `SEARCH`), the
operation fails with an `InvalidPayloadException`. An `INSERT` of a body that is not a document (such as plain
text, a byte array or a bean without `@Field` annotations) fails with the same exception, also when the request has
solr parameters (such as the commit the `autoCommit` option adds).

A field of a `Map` body or a `CamelSolrField.` header with a null value is left out of the document.

After each operation the message body is the response of Solr as a Map (a `SimpleOrderedMap`) with the
`responseHeader`, and for a search the documents under `response` as a `SolrDocumentList`. Convert it to a
`QueryResponse` to read it with SolrJ.

== Example

Below is a simple `INSERT`, `DELETE` and `SEARCH` example

[tabs]
====
Java::
+
[source,java]
----
from("direct:insert")
    .setHeader("CamelSolrOperation", constant("INSERT"))
    .setHeader("CamelSolrField.id", body())
    .to("solr://localhost:8983/solr/mycollection");

from("direct:delete")
    .setHeader("CamelSolrOperation", constant("DELETE"))
    .to("solr://localhost:8983/solr/mycollection");

from("direct:search")
    .setHeader("CamelSolrOperation", constant("SEARCH"))
    .to("solr://localhost:8983/solr/mycollection");
----

XML::
+
[source,xml]
----
<route>
    <from uri="direct:insert"/>
    <setHeader name="CamelSolrOperation">
        <constant>INSERT</constant>
    </setHeader>
    <setHeader name="CamelSolrField.id">
        <simple>${body}</simple>
    </setHeader>
    <to uri="solr://localhost:8983/solr/mycollection"/>
</route>
<route>
    <from uri="direct:delete"/>
    <setHeader name="CamelSolrOperation">
        <constant>DELETE</constant>
    </setHeader>
    <to uri="solr://localhost:8983/solr/mycollection"/>
</route>
<route>
    <from uri="direct:search"/>
    <setHeader name="CamelSolrOperation">
        <constant>SEARCH</constant>
    </setHeader>
    <to uri="solr://localhost:8983/solr/mycollection"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:insert
      steps:
        - setHeader:
            name: CamelSolrOperation
            expression:
              constant:
                expression: INSERT
        - setHeader:
            name: CamelSolrField.id
            expression:
              simple:
                expression: "${body}"
        - to:
            uri: solr://localhost:8983/solr/mycollection
- route:
    from:
      uri: direct:delete
      steps:
        - setHeader:
            name: CamelSolrOperation
            expression:
              constant:
                expression: DELETE
        - to:
            uri: solr://localhost:8983/solr/mycollection
- route:
    from:
      uri: direct:search
      steps:
        - setHeader:
            name: CamelSolrOperation
            expression:
              constant:
                expression: SEARCH
        - to:
            uri: solr://localhost:8983/solr/mycollection
----
====

A client would simply need to pass a body message to the insert or
delete routes, with the `CamelSolrParam.commit` header to commit the change.

._Java-only: sending messages to Solr routes using ProducerTemplate_
[source,java]
----
template.sendBodyAndHeader("direct:insert", "1234", "CamelSolrParam.commit", true);
template.sendBodyAndHeader("direct:delete", "1234", "CamelSolrParam.commit", true);
template.sendBody("direct:search", "id:1234");
----

For more information:

https://solr.apache.org/guide/solr/latest/[Apache Solr Reference Guide]
