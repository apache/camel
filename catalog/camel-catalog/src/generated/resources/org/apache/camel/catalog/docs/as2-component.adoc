The AS2 component provides transport of EDI messages using the HTTP transfer protocol
as specified in https://tools.ietf.org/html/rfc4130[RFC4130]. 

Maven users will need to add the following dependency to their pom.xml
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-as2</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

----
as2://apiName/methodName
----

apiName can be one of:

* client
* server

producers, strip these internal headers at the trust boundary -- for example with

== Usage

An `as2://server/listen` consumer receives AS2 messages on `serverPortNumber`, for the request URIs that match
`requestUriPattern`. When its route fails, the partner gets an HTTP 500 that only says the message could not be
processed; set `muteException=false` to send the message of the exception too. An `as2://client/send` producer sends the message body (`inBody: ediMessage`) to
`targetHostname` and `targetPortNumber`. The following routes send a plain EDIFACT message from one to the other:

[source,yaml]
----
- route:
    from:
      uri: as2://server/listen
      parameters:
        serverPortNumber: 8888
        requestUriPattern: /receiver
      steps:
        - log:
            message: "Received EDI message: ${body}"
- route:
    from:
      uri: timer:send
      parameters:
        repeatCount: 1
      steps:
        - setBody:
            expression:
              constant:
                expression: "UNB+UNOA:1+SENDER+RECEIVER+260101:1200+1'UNZ+1+1'"
        - to:
            uri: as2://client/send
            parameters:
              inBody: ediMessage
              targetHostname: localhost
              targetPortNumber: 8888
              requestUri: /receiver
              as2From: sender
              as2To: receiver
              from: sender@example.com
              subject: Order
              as2MessageStructure: PLAIN
              ediMessageContentType: application/edifact
----

A `SIGNED`, `ENCRYPTED` or `SIGNED_ENCRYPTED` message structure also needs the keys and certificates of the signing
and encrypting options.

Several `as2://server/listen` consumers can share a `serverPortNumber`, each with its own `requestUriPattern`. Each
consumer applies its own keys and certificates and its own asynchronous MDN settings (`mdnUserName`, `mdnPassword`,
`mdnAccessToken` and `asyncMdnAllowedHosts`) to the messages received on its own pattern.

The settings of the shared server connection still come from the first endpoint created on the port:
`sslContextParameters` and `sslContext` (used for the TLS listener and for the https delivery of asynchronous MDNs),
`mdnMessageTemplate`, `server`, `serverFqdn` and `as2Version`. They are per port, not per consumer.
