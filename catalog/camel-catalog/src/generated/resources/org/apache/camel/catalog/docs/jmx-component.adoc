Apache Camel has extensive support for JMX to allow you to monitor and
control the Camel managed objects with a JMX client.

Camel also provides a xref:jmx-component.adoc[JMX] component that allows you to
subscribe to MBean notifications. This page is about how to manage and
monitor Camel using JMX.

[NOTE]
====
If you run Camel standalone with just `camel-core` as a dependency, and you want JMX to enable out of the box, then you need to add `camel-management` as a dependency.
====

== Usage

The JMX consumer receives the notifications of an MBean.
With `monitorType`, it creates a JMX monitor that watches an attribute,
and sends a notification when the value crosses a threshold.
`jmx:platform` is the MBean server of the JVM that runs Camel.
The route below gets a notification when the JVM has more than 200 threads.
The gauge sends it again only after the value has gone below `thresholdLow`:

[source,yaml]
----
- route:
    from:
      uri: jmx:platform
      parameters:
        objectDomain: java.lang
        key.type: Threading
        monitorType: gauge
        observedAttribute: ThreadCount
        granularityPeriod: 5000
        notifyHigh: true
        thresholdHigh: 200
        thresholdLow: 100
      steps:
        - log:
            message: "The JVM has more than 200 threads: ${body}"
----

The message body is the notification as XML. Set `format` to `raw` to get the notification object.
