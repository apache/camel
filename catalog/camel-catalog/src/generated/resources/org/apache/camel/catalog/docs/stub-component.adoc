The Stub component provides a simple way to stub out any physical
endpoints while in development or testing, allowing you, for example, to
run a route without needing to actually connect to a specific
xref:mail-component.adoc[SMTP] or xref:http-component.adoc[Http] endpoint.
Add *stub:*
in front of any endpoint URI to stub out the endpoint.

== URI format

----
stub:someUri
----

Where *`someUri`* can be any URI with any query parameters.

== Usage

Internally, the Stub component creates xref:seda-component.adoc[Seda] endpoints.
The main difference between xref:stub-component.adoc[Stub] and xref:seda-component.adoc[Seda] is
that xref:seda-component.adoc[Seda] will validate the URI and parameters you give it,
so putting seda: in front of a typical URI with query arguments will
usually fail.
Stub won't, though, as it basically ignores all query
parameters to let you quickly stub out one or more endpoints in your
route temporarily.

=== Stub endpoints without a consumer

A stub endpoint that no route consumes from keeps the latest messages sent to it, so you can browse them,
for example with `camel cmd stub --browse` from the xref:manual::camel-jbang.adoc[Camel CLI].
It keeps up to `size` messages (1000 by default), and when the queue is full, it drops the oldest message
to make room for the new one. Sending to a stub endpoint without a consumer therefore never fails with `Queue full`,
and the memory it uses stays bounded.

When a route consumes from the stub endpoint, the messages are queued as with xref:seda-component.adoc[Seda],
and the `size`, `blockWhenFull` and `discardWhenFull` options apply as usual.

== Examples

Here are a few samples of stubbing endpoint uris

----
stub:smtp://somehost.foo.com?user=whatnot&something=else
stub:http://somehost.bar.com/something
----

In a route, put `stub:` in front of the endpoint you do not want to call.
The message goes to an in-memory queue instead.
Another route can read the queue from the same stub endpoint, for example to log what would have been sent.
The query parameters do not matter: `stub:smtp://somehost.foo.com` is the same queue.

[source,yaml]
----
- route:
    from:
      uri: timer:orders
      parameters:
        repeatCount: 1
      steps:
        - setBody:
            expression:
              constant:
                expression: A new order has arrived
        - to:
            uri: "stub:smtp://somehost.foo.com?user=whatnot&something=else"
- route:
    from:
      uri: "stub:smtp://somehost.foo.com"
      steps:
        - log:
            message: "Stubbed mail: ${body}"
----
