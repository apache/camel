The Spring AI Vector Store component provides support for storing and retrieving documents in vector databases using https://docs.spring.io/spring-ai/reference/api/vectordbs.html[Spring AI] vector store capabilities.

Vector stores enable:

* Storage of documents with embeddings
* Similarity search based on vector distance
* Metadata-based filtering
* Document management (add, upsert, delete)

== URI format

----
spring-ai-vector-store:storeId[?options]
----

Where *storeId* can be any string to uniquely identify the endpoint

== Operations

The component supports four operations:

=== ADD Operation

Stores documents in the vector store. Can accept:

* String text (embeddings will be generated automatically)
* Document objects
* List of Documents or of String texts (an element of another type fails)
* Output from the spring-ai-embeddings component (semi-automatic integration, this depends on the underlying Spring AI Vectore Store implementation):
a `float[]` body with the `CamelSpringAiEmbeddingInputText` header, or a List of `float[]` body with the
`CamelSpringAiEmbeddingInputTexts` header with one text per vector. A vector without its text fails.

The `CamelSpringAiEmbeddingInputText(s)` headers are only used together with a vector body, so a header left over from
an earlier spring-ai-embeddings call does not replace a Document or text body.

ADD of a vector stores its text, and the vector store embeds the text again with its own embedding model. The vector
only goes in the `embedding` metadata of the document. To store the vector itself, use UPSERT.

After documents are added, the component sets the `CamelSpringAiVectorStoreDocumentIds` header containing a list of the IDs of the added documents. This allows you to reference or track the stored documents in subsequent processing steps.

NOTE: *Best Practice:* Use the ADD operation directly with the vector store component when working with text. The component will automatically handle embedding generation internally if the vector store is configured with an embedding model. This is the recommended approach as it simplifies your routes and reduces the number of steps.

=== UPSERT Operation

Writes vectors that are already computed, such as the output of the spring-ai-embeddings component, as they are. The
embedding model of the vector store is not called. A document with the same ID is replaced, otherwise a new document is
added. UPSERT takes:

* A `float[]` body with the `CamelSpringAiEmbeddingInputText` header, the text of the vector. The
`CamelSpringAiVectorStoreUpsertDocumentId` header is the ID of the document. Without it, the document gets a random UUID.
* A List of `float[]` body with the `CamelSpringAiEmbeddingInputTexts` header, with one text per vector. The
`CamelSpringAiVectorStoreUpsertDocumentIds` header is the List of IDs, with one ID per vector. Without it, each document
gets a random UUID.
* A Spring AI `EmbeddedDocument` (a Document with its vector), or a List of `EmbeddedDocument`. The ID and the metadata
are the ones of the Document, and the ID headers are not used.

A vector without its text fails, and so does a List of texts or of IDs with another size than the List of vectors.
UPSERT does not write the `embedding` and `precomputed_embedding` metadata of ADD.

Like ADD, UPSERT sets the `CamelSpringAiVectorStoreDocumentsAdded` header to the number of documents written, and the
`CamelSpringAiVectorStoreDocumentIds` header to their IDs. UPSERT does not read the IDs from
`CamelSpringAiVectorStoreDocumentIds`, as ADD, UPSERT and SIMILARITY_SEARCH set this header to their own output IDs.

The vector store must support UPSERT. In Spring AI 2.1, the Chroma, Couchbase, Elasticsearch, MariaDB, MongoDB Atlas,
Neo4j, OpenSearch, PgVector, Qdrant, Redis and Typesense vector stores do. With another vector store, such as
`SimpleVectorStore`, UPSERT fails with an `UnsupportedOperationException` and nothing is written: use ADD instead.
Some vector stores only accept IDs in a given format, for example Qdrant needs UUIDs.

=== DELETE Operation

Removes documents from the vector store by their IDs. The body has the documents to delete: an ID, a Document, or a
List of IDs or of Documents (such as the result of SIMILARITY_SEARCH). Only when there is no body, the IDs are taken
from the `CamelSpringAiVectorStoreDocumentIds` header. The body comes first because ADD and SIMILARITY_SEARCH set this
header to their own output IDs.

The `CamelSpringAiVectorStoreDocumentsDeleted` header is the number of IDs given to the vector store. The Spring AI
`VectorStore` API does not tell how many of them existed, so IDs that are not in the store are counted too.

=== SIMILARITY_SEARCH Operation

Searches for documents similar to a query text. After the spring-ai-embeddings component, where the body is the
`float[]` vector of the text, the query is the text in the `CamelSpringAiEmbeddingInputText` header (the vector store
embeds the query itself).

With the `searchByVector` option, the `float[]` body is the query: the vector store searches with this vector, and does
not embed a text. The `CamelSpringAiEmbeddingInputText` header is then not needed. A text body is still searched as a
text. The vector store must support the search with a vector, as for UPSERT, otherwise the search fails with an
`UnsupportedOperationException`. The `topK`, `similarityThreshold` and `filterExpression` options and headers apply as
for a text.

The component returns matching documents in the message body and sets the following headers:

* `CamelSpringAiVectorStoreSimilarDocuments` - List of Document objects found
* `CamelSpringAiVectorStoreDocumentIds` - List of IDs of the found documents

=== ADD or UPSERT

* With ADD and a text query, the vector store embeds the texts with its own embedding model, when it writes and when it
searches. This is the simplest way.
* With UPSERT and `searchByVector`, the route computes the vectors, for example with the spring-ai-embeddings
component, and the vector store writes and searches with these vectors as they are. Use it to choose the embedding
model in the route, or to embed each text only once.

IMPORTANT: Use the same embedding model, with the same settings, to write and to search. A vector of another model gives
meaningless results, and no error is raised. This also applies when you mix the operations: documents written with
UPSERT and searched with a text use the embedding model of the vector store for the query, and documents written with
ADD and searched with `searchByVector` use the model of the route for the query.

== Usage Examples

=== Add Documents from Text (Recommended)

This is the *recommended best practice* for adding documents. The vector store component handles embedding generation internally:

[tabs]
====
Java::
+
[source,java]
----
from("direct:store")
    .to("spring-ai-vector-store:myStore?operation=ADD&vectorStore=#vectorStore");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:store"/>
  <to uri="spring-ai-vector-store:myStore?operation=ADD&amp;vectorStore=#vectorStore"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:store
      steps:
        - to:
            uri: spring-ai-vector-store:myStore
            parameters:
              operation: ADD
              vectorStore: "#vectorStore"
----
====

When you send plain text to this route, the component automatically:
1. Generates embeddings using the embedding model configured in the vector store
2. Creates a Document object
3. Stores it in the vector store

This single-step approach is simpler and more efficient than manually chaining the embeddings component.

=== Add from Embeddings Component (Alternative)

If you need explicit control over the embedding process or want to manipulate embeddings before storing, you can chain the components:

[tabs]
====
Java::
+
[source,java]
----
from("direct:embedAndStore")
    .to("spring-ai-embeddings:test?embeddingModel=#embeddingModel")
    .to("spring-ai-vector-store:test?vectorStore=#vectorStore");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:embedAndStore"/>
  <to uri="spring-ai-embeddings:test?embeddingModel=#embeddingModel"/>
  <to uri="spring-ai-vector-store:test?vectorStore=#vectorStore"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:embedAndStore
      steps:
        - to:
            uri: spring-ai-embeddings:test
            parameters:
              embeddingModel: "#embeddingModel"
        - to:
            uri: spring-ai-vector-store:test
            parameters:
              vectorStore: "#vectorStore"
----
====

NOTE: This approach is only necessary when you need to access or modify the embeddings between generation and storage. For most use cases, the direct ADD operation (shown above) is preferred.
With ADD, the vector store embeds the text again: to store the vectors of the embeddings component, use UPSERT (shown below).

=== Store and Search with the Vectors of the Embeddings Component

UPSERT stores the vectors that the spring-ai-embeddings component computes, and `searchByVector` searches with the
vector of the query. The vector store does not embed any text, so it must support UPSERT and the search with a vector.

[tabs]
====
Java::
+
[source,java]
----
from("direct:store")
    .to("spring-ai-embeddings:embed?embeddingModel=#embeddingModel")
    .to("spring-ai-vector-store:myStore?operation=UPSERT&vectorStore=#vectorStore");

from("direct:search")
    .to("spring-ai-embeddings:embed?embeddingModel=#embeddingModel")
    .to("spring-ai-vector-store:myStore?operation=SIMILARITY_SEARCH&searchByVector=true&topK=5&vectorStore=#vectorStore");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:store"/>
  <to uri="spring-ai-embeddings:embed?embeddingModel=#embeddingModel"/>
  <to uri="spring-ai-vector-store:myStore?operation=UPSERT&amp;vectorStore=#vectorStore"/>
</route>
<route>
  <from uri="direct:search"/>
  <to uri="spring-ai-embeddings:embed?embeddingModel=#embeddingModel"/>
  <to uri="spring-ai-vector-store:myStore?operation=SIMILARITY_SEARCH&amp;searchByVector=true&amp;topK=5&amp;vectorStore=#vectorStore"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:store
      steps:
        - to:
            uri: spring-ai-embeddings:embed
            parameters:
              embeddingModel: "#embeddingModel"
        - to:
            uri: spring-ai-vector-store:myStore
            parameters:
              operation: UPSERT
              vectorStore: "#vectorStore"
- route:
    from:
      uri: direct:search
      steps:
        - to:
            uri: spring-ai-embeddings:embed
            parameters:
              embeddingModel: "#embeddingModel"
        - to:
            uri: spring-ai-vector-store:myStore
            parameters:
              operation: SIMILARITY_SEARCH
              searchByVector: true
              topK: 5
              vectorStore: "#vectorStore"
----
====

To replace a document, for example when its text changes, set its ID in the `CamelSpringAiVectorStoreUpsertDocumentId`
header (or the IDs in `CamelSpringAiVectorStoreUpsertDocumentIds` for a List of texts) before UPSERT.

=== Similarity Search

[tabs]
====
Java::
+
[source,java]
----
from("direct:search")
    .setBody(constant("What is AI?"))
    .to("spring-ai-vector-store:myStore?operation=SIMILARITY_SEARCH&topK=5&similarityThreshold=0.7")
    .log("Found ${header.CamelSpringAiVectorStoreSimilarDocuments.size()} similar documents")
    .log("Document IDs: ${header.CamelSpringAiVectorStoreDocumentIds}");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:search"/>
  <setBody><constant>What is AI?</constant></setBody>
  <to uri="spring-ai-vector-store:myStore?operation=SIMILARITY_SEARCH&amp;topK=5&amp;similarityThreshold=0.7"/>
  <log message="Found ${header.CamelSpringAiVectorStoreSimilarDocuments.size()} similar documents"/>
  <log message="Document IDs: ${header.CamelSpringAiVectorStoreDocumentIds}"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:search
      steps:
        - setBody:
            constant: "What is AI?"
        - to:
            uri: spring-ai-vector-store:myStore
            parameters:
              operation: SIMILARITY_SEARCH
              topK: 5
              similarityThreshold: 0.7
        - log:
            message: "Found ${header.CamelSpringAiVectorStoreSimilarDocuments.size()} similar documents"
        - log:
            message: "Document IDs: ${header.CamelSpringAiVectorStoreDocumentIds}"
----
====

=== Delete Documents

Delete documents by specifying their IDs in the body:

._Java-only: Arrays.asList()_
[source,java]
----
from("direct:delete")
    .setBody(constant(Arrays.asList("doc1", "doc2")))
    .to("spring-ai-vector-store:myStore?operation=DELETE");
----

You can also chain operations to search for documents and then delete the documents found:

._Java-only: Java constants and enum values_
[source,java]
----
from("direct:searchAndDelete")
    .setBody(constant("outdated content"))
    .to("spring-ai-vector-store:myStore?operation=SIMILARITY_SEARCH&topK=10")
    .log("Found ${header.CamelSpringAiVectorStoreDocumentIds.size()} documents to delete")
    // DELETE deletes the List of Document that SIMILARITY_SEARCH gives in the body
    .setHeader(SpringAiVectorStoreHeaders.OPERATION, constant(SpringAiVectorStoreOperation.DELETE))
    .to("spring-ai-vector-store:myStore");
----

=== Dynamic Operation

._Java-only: Java constants and enum values_
[source,java]
----
from("direct:dynamic")
    .setHeader(SpringAiVectorStoreHeaders.OPERATION, constant(SpringAiVectorStoreOperation.ADD))
    .to("spring-ai-vector-store:myStore");
----

== Configuration

=== Configuring the Vector Store

To use the ADD operation with automatic embedding generation (recommended), configure your vector store with an embedding model:

._Java-only: Java Spring AI SDK configuration_
[source,java]
----
// Create a Qdrant Client
QdrantClient qdrantClient
                = new QdrantClient(QdrantGrpcClient.newBuilder(QDRANT.getGrpcHost(), QDRANT.getGrpcPort(), false).build());

// Create an embedding model
EmbeddingModel embeddingModel = new OllamaEmbeddingModel(ollamaApi, options);

// Create a vector store with the embedding model
// Example with Qdrant
VectorStore vectorStore = QdrantVectorStore.builder(qdrantClient, embeddingModel)
    .collectionName("my_collection")
    .initializeSchema(true)
    .build();

// Or with Simple Vector Store
VectorStore vectorStore = new SimpleVectorStore(embeddingModel);

// Register in Camel context
context.getRegistry().bind("vectorStore", vectorStore);

// Use in route - the component will use the configured embedding model
from("direct:start")
    .to("spring-ai-vector-store:test?vectorStore=#vectorStore&operation=ADD");
----

IMPORTANT: Make sure your vector store is configured with an embedding model to enable automatic embedding generation when using the ADD operation with text input.

=== Search Parameters

* `topK` - Maximum number of results (default: 5)
* `similarityThreshold` - Minimum similarity score 0-1 (default: 0.0)
* `filterExpression` - Metadata-based filter expression
* `searchByVector` - Search with the `float[]` body instead of the text of the `CamelSpringAiEmbeddingInputText` header (default: false)
