= InfluxDB2 Component
:doctitle: InfluxDB2
:shortname: influxdb2
:artifactid: camel-influxdb2
:description: Interact with InfluxDB v2, a time series database.
:since: 3.20
:supportlevel: Stable
:tabs-sync-option:
:component-header: Only producer is supported

*Since Camel {since}*

*{component-header}*

This component allows you to interact with https://influxdata.com/time-series-platform/influxdb/[InfluxDB] 2.x,
a time series database.
The native body type for this component is `Point` (the native InfluxDB class).
However, it can also accept `Map<String, Object>` as message body, and it will get converted to `Point.class`, please note that the map must contain an element with `CamelInfluxDB2MeasurementName` as key.
The other entries of the map are the fields of the point; the map itself is not changed, so it can be immutable.

Additionally, you may register your own Converters to your data type to `Point`, or use the (un)marshalling tools provided by Camel.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
------------------------------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-influxdb2</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
------------------------------------------------------------

== Example

Below is an example route that stores a point into the db (taking the db name from the URI) specific key:

[tabs]
====
Java::
+
[source,java]
----
from("direct:start")
        .to("influxdb2://connectionBean?org=myOrg&bucket=myBucket");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:start"/>
  <to uri="influxdb2://connectionBean?org=myOrg&amp;bucket=myBucket"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:start
      steps:
        - to:
            uri: influxdb2://connectionBean
            parameters:
              org: myOrg
              bucket: myBucket
----
====

== Writes are synchronous

The producer writes with the synchronous write API of the InfluxDB client (`WriteApiBlocking`): the exchange
continues when InfluxDB has answered the write request.
A write that InfluxDB rejects (for example, a line it cannot parse, an unknown bucket or a token that is not
authorized), or a request that cannot be sent, fails the exchange with a `CamelInfluxDb2Exception` whose cause is the
`InfluxException` of the client, so the error handler of the route can redeliver it or move it to a dead letter channel.

Each exchange is one write request. To write many points with one request, send a `Points`, `Measurements` or
`Records` body, for example, from an xref:eips:aggregate-eip.adoc[Aggregate] EIP.

InfluxDB needs at least one field in a point, and the client skips a point without a field that has a value (no field
at all, or only fields whose value is `null`, NaN or infinite) instead of writing it. Such a `Point`, also one converted
from a `Map` or one of the points of a `Points` body, fails the exchange with a `CamelInfluxDb2Exception`, and nothing
is written.

== Organization and bucket at startup

When `autoCreateOrg` is `true` (the default), the endpoint looks the organization up when it starts and creates it when
it does not exist. When `autoCreateBucket` is `true` (the default), it does the same for the bucket, in the organization
of the endpoint. With `autoCreateOrg=false`, a missing bucket is created only when that organization exists, and
otherwise the endpoint fails to start.

A write names the organization and the bucket, so the endpoint does not need them to be looked up: with
`autoCreateOrg=false` and `autoCreateBucket=false` it does not call InfluxDB when it starts, and the route starts while
InfluxDB is down. An organization or a bucket that does not exist then fails the write, and so the exchange.
