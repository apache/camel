//Manually maintained attributes

*Since Camel {since}*

*{component-header}*

This component allows sending and receiving messages from
https://redis.io/[Redis]. Redis is an advanced key-value store where
keys can contain strings, hashes, lists, sets and sorted sets. In
addition, it provides pub/sub functionality for inter-app
communications.
Camel provides a producer for executing commands, consumer for
subscribing to pub/sub messages an idempotent repository for filtering
out duplicate messages.

[NOTE]
====
*Prerequisites*

To use this component, you must have a Redis server running.
====

=== Examples

The producer runs the command of the `command` option, or of the `CamelRedis.Command` header.
The parameters of the command come from headers, such as `CamelRedis.Key` and `CamelRedis.Value`, not from the
message body. The tables below list the parameters of each command. The result of the command becomes the message body,
and a command without a result, such as `SET`, leaves the body as it was. A command that reads one value sets the body
to `null` when there is no value, such as `GET` of a missing key:

[source,yaml]
----
- route:
    from:
      uri: direct:save-greeting
      steps:
        - setHeader:
            name: CamelRedis.Key
            expression:
              constant:
                expression: greeting
        - setHeader:
            name: CamelRedis.Value
            expression:
              simple:
                expression: "${body}"
        - to:
            uri: spring-redis:localhost:6379
            parameters:
              command: SET
- route:
    from:
      uri: direct:read-greeting
      steps:
        - setHeader:
            name: CamelRedis.Key
            expression:
              constant:
                expression: greeting
        - to:
            uri: spring-redis:localhost:6379
            parameters:
              command: GET
        - log:
            message: "The greeting is ${body}"
----

The consumer needs `command` set to `SUBSCRIBE` (channel names) or `PSUBSCRIBE` (channel patterns), and receives the
messages posted to these channels. A producer posts a message with `PUBLISH`:

[source,yaml]
----
- route:
    from:
      uri: spring-redis:localhost:6379
      parameters:
        command: SUBSCRIBE
        channels: orders
      steps:
        - log:
            message: "Order event: ${body}"
- route:
    from:
      uri: direct:publish-order
      steps:
        - setHeader:
            name: CamelRedis.Channel
            expression:
              constant:
                expression: orders
        - setHeader:
            name: CamelRedis.Message
            expression:
              simple:
                expression: "${body}"
        - to:
            uri: spring-redis:localhost:6379
            parameters:
              command: PUBLISH
----

By default, keys and values are stored with Java serialization, so other Redis clients do not find the key `greeting`.
To store plain strings, set a `StringRedisSerializer` as the `serializer`, on every endpoint that reads or writes
these keys:

[source,yaml]
----
- route:
    from:
      uri: direct:save-greeting
      steps:
        - setHeader:
            name: CamelRedis.Key
            expression:
              constant:
                expression: greeting
        - setHeader:
            name: CamelRedis.Value
            expression:
              simple:
                expression: "${body}"
        - to:
            uri: spring-redis:localhost:6379
            parameters:
              command: SET
              serializer: "#class:org.springframework.data.redis.serializer.StringRedisSerializer"
----

The `KEYS` command sends its pattern through the key serializer too. With the default Java serialization a stored key
starts with the bytes of the serialization header, so a pattern such as `order-*` matches no key. Use `KEYS` with
keys stored as plain strings: set a `StringRedisSerializer` as the `serializer` as above, or, to keep Java
serialization for the values, a `redisTemplate` with a `StringRedisSerializer` as its key serializer:

[source,java]
----
RedisTemplate<String, Object> template = new RedisTemplate<>();
template.setConnectionFactory(connectionFactory);
template.setKeySerializer(new StringRedisSerializer());
template.setHashKeySerializer(new StringRedisSerializer());
template.afterPropertiesSet();
----

The consumer deserializes each message with the `serializer`, which is Java serialization by default. A message
that the serializer cannot read, such as one posted as text by `redis-cli PUBLISH` or another Redis client, is given
to the route as its raw bytes (`byte[]`). To receive such messages as text, set
`serializer=#class:org.springframework.data.redis.serializer.StringRedisSerializer` on the consumer. When the route
fails to process a message, the exchange is handed to the exception handler of the consumer (see the
`exceptionHandler` and `bridgeErrorHandler` options).

=== Message headers evaluated by the Redis producer

The producer issues commands to the server, and each command has
a different set of parameters with specific types. The result from the
command execution is returned in the message body. A command whose result is `void` leaves the body as it was.
The value commands, such as `GET`, `HGET` and `LPOP`, return the object that was stored: with the default serializer
the Java object the `CamelRedis.Value` header held.

The commands that read one value set the body to `null` when there is no value, such as `GET` of a key that does not
exist, so a route can tell a miss from a value. These are `GET`, `GETSET`, `HGET`, `LINDEX`, `LPOP`, `RPOP`,
`BLPOP`, `BRPOP` (also when the timeout passes), `RPOPLPUSH`, `BRPOPLPUSH`, `SPOP`, `SRANDMEMBER`, `RANDOMKEY`,
`ZSCORE`, `ZRANK`, `ZREVRANK` and `GEODIST`.

The `CamelRedis.Keys` header is a `Collection<String>`, or a `String` with one key or several keys separated by
comma (a key that holds a comma needs the `Collection` form).

The producer fails the exchange when the command is not one of the commands listed below: an unknown command fails
with an `IllegalArgumentException`, and a command of the `command` option that the producer does not run (such as
`AUTH`, `FLUSHDB`, `INFO` or `SELECT`) fails with an `UnsupportedOperationException`. `SUBSCRIBE` and `PSUBSCRIBE`
are for the consumer; the producer posts messages with `PUBLISH`.

== Dependencies

Maven users will need to add the following dependency to their pom.xml.

*pom.xml*

[source,xml]
-----------------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-spring-redis</artifactId>
    <version>${camel-version}</version>
</dependency>
-----------------------------------------------

where `${camel-version`} must be replaced by the actual version of Camel.
