The Milo Server component provides an OPC UA server using the
http://eclipse.org/milo[Eclipse Milo™] implementation.

*Java 11+*: This component requires Java 11+ at runtime.

NOTE: This component uses Eclipse Milo 1.0.5. When migrating from earlier versions,
be aware that the Milo API has undergone significant changes in the 1.0.x series.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
------------------------------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-milo</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
------------------------------------------------------------

Messages sent to the endpoint from Camel will be available from the OPC UA server to OPC UA Clients.
Value write requests from OPC UA Client will trigger messages which are sent into Apache Camel.

== Usage

A `milo-server` endpoint is an item of the OPC UA server that the component runs.
A producer writes the value of the item, and a consumer receives the values that OPC UA clients write to it.
The node ID of an item is its name in the namespace of the component (`urn:org:apache:camel` by default),
such as `nsu=urn:org:apache:camel;s=temperature`.

The server is configured with component options, for example in `application.properties`.
Clients log in with one of the users of `userAuthenticationCredentials`.
The security policy `None` is for trying the server out; use a secure policy in production:

[source,properties]
----
camel.component.milo-server.port = 12685
camel.component.milo-server.user-authentication-credentials = camel:secret
camel.component.milo-server.username-security-policy-uri = None
camel.component.milo-server.security-policies-by-id = None
----

The following routes write a temperature every five seconds, and log the setpoint that a client writes.
The body of the consumer is a `DataValue`, and `${body.value.value}` is the value itself:

[source,yaml]
----
- route:
    from:
      uri: timer:sample
      parameters:
        period: 5000
      steps:
        - setBody:
            expression:
              simple:
                expression: "${random(15,25)}"
        - to:
            uri: milo-server:temperature
- route:
    from:
      uri: milo-server:setpoint
      steps:
        - log:
            message: "A client wrote the setpoint: ${body.value.value}"
----

=== Security Configuration

When configuring security for the OPC UA server, the following considerations apply:

* Certificate validation uses `org.eclipse.milo.opcua.stack.core.security.CertificateValidator`
* The component supports both certificate-based and username/password authentication
* Security policies can be configured using the `securityPolicies` or `securityPoliciesById` options

==== Validating the certificates of the clients

On an endpoint with a security policy other than `None`, the server validates the certificate of each client.
Use one of these options:

* `defaultCertificateValidator`: the directory of a file based trust list. The server accepts the client
  certificates that are trusted in that directory (or issued by a trusted CA), and puts the rejected ones in
  `rejected/certs`.
* `certificateValidator`: a custom `CertificateValidator`, for example from the registry
  (`#myCertificateValidator`). It needs `certificateManager`, which holds the certificate and the key pair of the server. The
  server validates the client certificates with this validator instead of the validators of the certificate groups
  of `certificateManager`.

The two options cannot be used together: when both are set, the server fails to start.

For example, with a certificate manager, the server certificate and a validator bound in the registry:

[source,properties]
----
camel.component.milo-server.certificate-manager = #myCertificateManager
camel.component.milo-server.certificate = #myServerCertificate
camel.component.milo-server.certificate-validator = #myCertificateValidator
camel.component.milo-server.security-policies-by-id = Basic256Sha256
----

==== Anonymous clients for development

When neither `userAuthenticationCredentials` nor `enableAnonymousAuthentication` is set, the JVM system property
`org.apache.camel.milo.server.default.enableAnonymous=true` makes the endpoints of the server offer the Anonymous
user token policy (next to UserName and X509), and lets clients connect without a user name.
The property is off by default. It is meant for development and testing only: do not set it in production.

==== Milo 1.0.5 Migration Notes

With Milo 1.0.5, several security-related API changes were introduced:

* The `ServerCertificateValidator` class has been replaced with `CertificateValidator`
* Certificate validation now uses `org.eclipse.milo.opcua.stack.core.security.CertificateValidator`
* When configuring custom certificate validators programmatically, ensure you're using the updated API
