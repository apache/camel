:artifactid: camel-duckdb

*Since Camel {since}*

*{component-header}*

This component integrates with https://duckdb.org/[DuckDB] using the official JDBC driver
(`org.duckdb:duckdb_jdbc`). It focuses on embedded databases (`:memory:` or file paths), SQL
`execute`/`query`, structured batch `insert`, file `copy` (CSV, Parquet, JSON), and `ping`.

While DuckDB can be used through xref:jdbc-component.adoc[JDBC] and xref:sql-component.adoc[SQL],
this component exposes DuckDB-oriented URI options and headers without hand-wiring JDBC URLs in
every route.

Maven users will need to add the following dependency to their `pom.xml`:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-duckdb</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

----
duckdb:databasePath?[options]
----

Configure `databasePath` as `:memory:` or a file path, either relative (`analytics.db`) or absolute
(`/data/analytics.db`). The default table for `insert` and `copy` is set with the `table` option.
Alternatively set `jdbcUrl=jdbc:duckdb:...` to override the built URL, or autowire a shared
`javax.sql.DataSource`.

== Operations

The producer supports:

* `execute` (default) — run DDL/DML from the message body (or `query` option / `CamelDuckDbQuery` header)
* `query` — run a SELECT and return rows as `List<Map>` (default) or JSON (`resultFormat=JSON`)
* `insert` — insert a `List` of `Map` rows into `table`
* `copy` — bulk load one local file, from a `File` or a path `String`, using DuckDB `read_csv` / `read_parquet` / `read_json`
* `ping` — `SELECT 1` connectivity check; sets `CamelDuckDbPingOk`

The endpoint reuses one JDBC connection for its configured `databasePath` / `jdbcUrl` and serializes access for
thread safety. Prefer a shared `DataSource` when you need concurrent producers. Set the
`CamelDuckDbDatabasePath` header to open a short-lived connection to a different database file for a single
message.

== Copy sources

The `copy` operation gives the path from the message body to the DuckDB `read_csv`, `read_parquet` or `read_json`
function. DuckDB reads a value that starts with a URL scheme (such as `https://` or `s3://`) as a remote file, and
expands a value with glob pattern characters (`*`, `?`, `[` or `{`) to all the matching files. So by default `copy`
loads a single local file, and fails with an `IllegalArgumentException` that names the option to set otherwise:

* `allowUrlCopySource=true` passes a source with a URL scheme to DuckDB as it is.
* `allowGlobCopySource=true` loads all the files that a glob pattern matches. This also applies to a `File` body
  whose name has one of these characters.
* `copyBaseDirectory` sets the directory that a local source must be inside, after resolving symbolic links. A
  relative source is resolved against this directory, and for a glob pattern the directory before the first glob
  character must be inside it.

[tabs]
====
Java::
+
[source,java]
----
from("direct:load")
    .to("duckdb:warehouse.db?operation=copy&table=staging&allowGlobCopySource=true&copyBaseDirectory=/data/incoming");
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:load
      steps:
        - to:
            uri: duckdb:warehouse.db
            parameters:
              operation: copy
              table: staging
              allowGlobCopySource: true
              copyBaseDirectory: /data/incoming
----
====

These options apply to `copy` only. The SQL of `execute` and `query` can call the read functions itself; to have
DuckDB restrict file and network access for every statement, configure the DuckDB settings
`enable_external_access`, `allowed_directories` and `autoinstall_known_extensions` (see the DuckDB documentation).

== Example

[source,java]
----
from("direct:metrics")
    .to("duckdb:local.db?operation=insert&table=metrics&batchSize=500");
----

[source,java]
----
from("file:incoming?include=.*\\.csv")
    .to("duckdb:warehouse.db?operation=copy&table=staging&format=csv");
----
