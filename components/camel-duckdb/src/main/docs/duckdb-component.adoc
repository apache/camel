= DuckDB Component
:doctitle: DuckDB
:shortname: duckdb
:artifactid: camel-duckdb
:description: Interact with DuckDB, the in-process analytical SQL database, for embedded analytics workloads.
:since: 4.22
:supportlevel: Preview

:component-header: Only producer is supported

*Since Camel {since}*

*{component-header}*

This component integrates with https://duckdb.org/[DuckDB] using the official JDBC driver
(`org.duckdb:duckdb_jdbc`). It focuses on embedded databases (`:memory:` or file paths), SQL
`execute`/`query`, structured batch `insert`, file `copy` (CSV, Parquet, JSON), and `ping`.

While DuckDB can be used through xref:jdbc-component.adoc[JDBC] and xref:sql-component.adoc[SQL],
this component exposes DuckDB-oriented URI options and headers without hand-wiring JDBC URLs in
every route.

Maven users will need to add the following dependency to their `pom.xml`:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-duckdb</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

----
duckdb:databasePath?[options]
----

Configure `databasePath` as `:memory:` or a file path, either relative (`analytics.db`) or absolute
(`/data/analytics.db`). The default table for `insert` and `copy` is set with the `table` option.
Alternatively set `jdbcUrl=jdbc:duckdb:...` to override the built URL, or autowire a shared
`javax.sql.DataSource`.

== Operations

The producer supports:

* `execute` (default) — run DDL/DML that returns no rows
* `query` — run a SELECT and return rows as `List<Map>` (default) or JSON (`resultFormat=JSON`)
* `insert` — insert a `List` of `Map` rows into `table`
* `copy` — bulk load from a `File`, a `Path` or a path as `String` (or bytes) using DuckDB `read_csv` / `read_parquet` / `read_json`
* `ping` — `SELECT 1` connectivity check; sets `CamelDuckDbPingOk`

The SQL for `execute` and `query` is taken from the `CamelDuckDbQuery` header, else from the `query` option, else
from the message body. So when the `query` option is set, the message body is not used as SQL.

A statement that returns rows fails with `execute`, and a statement that returns no rows (such as DDL) fails with
`query`; the error says which operation to use instead. DuckDB has run the statement when the error is raised.

The endpoint reuses one JDBC connection for its configured `databasePath` / `jdbcUrl` and serializes access for
thread safety. Prefer a shared `DataSource` when you need concurrent producers.

== Headers that override the endpoint

These headers take the place of an endpoint option for one message:

* `CamelDuckDbOperation` replaces the `operation` option.
* `CamelDuckDbQuery` replaces the `query` option and the message body as the SQL of `execute` and `query`.
* `CamelDuckDbTable` replaces the `table` option of `insert` and `copy`.

So a message that carries them chooses the operation, the SQL that runs and the table that is written to.

The `CamelDuckDbDatabasePath` header is ignored unless the endpoint sets `allowDatabasePathFromHeader=true`. With
that option, the header opens a short-lived connection to the DuckDB file at that path for one message, instead of
the `databasePath`, `jdbcUrl` or `DataSource` of the endpoint, and DuckDB creates the file when it does not exist.

When the messages come from an untrusted producer through a consumer that does not filter out `Camel*` headers,
remove these headers with `removeHeaders("CamelDuckDb*")` before the `duckdb` endpoint.

== Example

[tabs]
====
Java::
+
[source,java]
----
from("direct:metrics")
    .to("duckdb:local.db?operation=insert&table=metrics&batchSize=500");
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:metrics
      steps:
        - to:
            uri: duckdb:local.db
            parameters:
              operation: insert
              table: metrics
              batchSize: 500
----
====

[tabs]
====
Java::
+
[source,java]
----
from("file:incoming?include=.*\\.csv")
    .to("duckdb:warehouse.db?operation=copy&table=staging&format=csv");
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: file:incoming
      parameters:
        include: ".*\\.csv"
      steps:
        - to:
            uri: duckdb:warehouse.db
            parameters:
              operation: copy
              table: staging
              format: csv
----
====

A query returns the rows as a `List` of `Map`, or as a JSON array with `resultFormat=JSON`:

[source,yaml]
----
- route:
    from:
      uri: timer:report
      parameters:
        period: 60000
      steps:
        - to:
            uri: duckdb:warehouse.db
            parameters:
              operation: query
              query: "SELECT region, sum(amount) AS total FROM staging GROUP BY region"
              resultFormat: JSON
        - log:
            message: "${body}"
----
