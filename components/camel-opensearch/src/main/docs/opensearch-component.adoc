= OpenSearch Component
:doctitle: OpenSearch
:shortname: opensearch
:artifactid: camel-opensearch
:description: Send requests to OpenSearch via Java Client API.
:since: 4.0
:supportlevel: Stable
:tabs-sync-option:
:component-header: Only producer is supported

*Since Camel {since}*

*{component-header}*

The OpenSearch component allows you to interface with an
https://opensearch.org/[OpenSearch] 3.x API using the Java API Client library.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-opensearch</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== Usage

=== Message Operations

The following https://opensearch.org/[OpenSearch] operations are currently supported.
Set an endpoint URI option or exchange header with a key of "operation"
and a value set to one of the following. Some operations also require
other parameters or the message body to be set.

A request of the OpenSearch client in the message body, such as an `IndexRequest`, a `GetRequest` or a `SearchRequest`,
sets the operation by its type, whatever the option or header say, and is sent as it is: its index, id and the rest are
not changed by the headers or options.

[width="100%",cols="10%,10%,80%",options="header",]
|===
|operation |message body |description

|`Index` |`Map`, `String`, `byte[]`, `Reader`, `InputStream`, a file (`java.io.File`, `Path` or the file of the file component), `IndexRequest` or `IndexRequest.Builder` content to index |Adds content to an index and returns the content's indexId in the body.
A file is read as the JSON of the document, and a null body fails.
You can set the name of the target index by setting the message header with the key "indexName".
You can set the indexId by setting the message header with
the key "indexId".

|`GetById` |`String`, `GetRequest` or `GetRequest.Builder` index id of content to retrieve |Retrieves the document corresponding to the given index id and returns a GetResponse object in the body.
You can set the name of the target index by setting the message header with the key "indexName".
You can set the type of document by setting the message header with
the key "documentClass".

|`Delete` |`String`, `DeleteRequest` or `DeleteRequest.Builder` index id of content to delete |Deletes the specified indexName and returns a Result object in the body.
You can set the name of the target index by setting the message header with the key "indexName".

|`DeleteIndex` |`String` name of the index, `DeleteIndexRequest` or `DeleteIndexRequest.Builder` |Deletes the index named by the indexName header or option, or else the one named by a `String` body, and returns a `Boolean` in the body that is true when the deletion is acknowledged.
You can set the name of the target index by setting the message header with the key "indexName".

|`Bulk` |`Iterable`, `BulkRequest` or `BulkRequest.Builder` of any type that is already accepted (DeleteOperation.Builder for delete operation, UpdateOperation.Builder for update operation, CreateOperation.Builder for create operation, byte[], InputStream, String, Reader, Map or any document type for index operation) | Adds/Updates/Deletes content from/to an index and returns a List<BulkResponseItem> object in the body
You can set the name of the target index by setting the message header with the key "indexName".

|`Search` |`Map`, `String`, `SearchRequest` or `SearchRequest.Builder` |Search the content with the search request as a JSON `String` or a `Map`: its query, size, from, sort, aggregations, _source and the rest are used.
A JSON object with a single member other than query, such as `{"match": {...}}`, is the query alone.
You can set the name of the target index by setting the message header with the key "indexName".
You can set the number of hits to return by setting the message header with the key "size".
You can set the starting document offset by setting the message header with the key "from".
The size and from headers or options, when set, override those of the body.

|`MultiSearch` |`MsearchRequest` or `MsearchRequest.Builder` |Multiple search in one

|`MultiGet` |`Iterable<String>`, `MgetRequest` or `MgetRequest.Builder` the id of the document to retrieve |Multiple get in one

You can set the name of the target index by setting the message header with the key "indexName".

|`Exists` |None |Checks whether the index exists or not and returns a Boolean flag in the body.

You must set the name of the target index by setting the message header with the key "indexName".

|`Update` |`byte[]`, `InputStream`, `String`, `Reader`, `Map`, a file, `UpdateRequest`, `UpdateRequest.Builder` or any document type content to update |Updates content to an index and returns the content's indexId in the body.
A file is read as JSON, and a null body fails.
You can set the name of the target index by setting the message header with the key "indexName".
You can set the indexId by setting the message header with
the key "indexId".

|Ping |None  |Pings the OpenSearch cluster and returns true if the ping succeeded, false otherwise

|===

=== Configure the component and enable basic authentication
To use the OpenSearch component, it has to be configured with a minimum configuration.

._Java-only: programmatic CamelContext configuration_
[source,java]
----
OpensearchComponent opensearchComponent = new OpensearchComponent();
opensearchComponent.setHostAddresses("opensearch-host:9200");
camelContext.addComponent("opensearch", opensearchComponent);
----

For basic authentication with OpenSearch or using reverse http proxy in front of the OpenSearch cluster, simply setup
basic authentication and SSL on the component like the example below

._Java-only: programmatic CamelContext configuration_
[source,java]
----
OpenSearchComponent opensearchComponent = new OpenSearchComponent();
opensearchComponent.setHostAddresses("opensearch-host:9200");
opensearchComponent.setUser("opensearchuser");
opensearchComponent.setPassword("secure!!");

camelContext.addComponent("opensearch", opensearchComponent);
----


=== Custom clients per endpoint

Use the `openSearchClient` endpoint option to reference an
`org.opensearch.client.opensearch.OpenSearchClient` in the Camel registry.
Each endpoint can use a different client, allowing a single route to connect to
different OpenSearch services with their own authentication and transport settings.

[source,java]
----
camelContext.getRegistry().bind("firstClient", firstClient);
camelContext.getRegistry().bind("secondClient", secondClient);

from("direct:ping")
    .to("opensearch:first?operation=Ping&openSearchClient=#bean:firstClient")
    .to("opensearch:second?operation=Ping&openSearchClient=#bean:secondClient");
----

The endpoint client takes precedence over the component's `openSearchClient` and
`client` options. Without an endpoint override, the component's client configuration
continues to apply. Configure connection and authentication settings on the supplied
client; `hostAddresses` is not required when supplying a client.

The application owns supplied clients and must close them when they are no longer
needed. Camel does not close them when a route stops or when `disconnect=true`.

=== Document type

For all the search operations, it is possible to indicate the type of document to retrieve to get the result already unmarshalled with the expected type.

The document type can be set using the header "documentClass" or via the uri parameter of the same name.

== Examples

=== Index Example

Below is a simple INDEX example

[tabs]
====
Java::
+
[source,java]
----
from("direct:index")
    .to("opensearch://opensearch?operation=Index&indexName=twitter");
----

XML::
+
[source,xml]
----
<route>
    <from uri="direct:index"/>
    <to uri="opensearch://opensearch?operation=Index&amp;indexName=twitter"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:index
      steps:
        - to:
            uri: opensearch://opensearch
            parameters:
              operation: Index
              indexName: twitter
----
====

NOTE: The indexId header (`CamelOpensearchIndexId`) is optional: without it, the server generates the id of the document.

A client would simply need to pass a body message containing a Map to
the route. The result body contains the indexId created.

._Java-only: Java test API (ProducerTemplate)_
[source,java]
----
Map<String, String> map = new HashMap<String, String>();
map.put("content", "test");
String indexId = template.requestBody("direct:index", map, String.class);
----

=== Custom OpenSearchClient Example

You can provide a pre-configured `OpenSearchClient` instance instead of letting the component
build one from host addresses. This is useful when you need a custom transport, for example
when connecting to AWS OpenSearch Service with IAM-based authentication.

._Java-only: programmatic CamelContext configuration_
[source,java]
----
// Build a custom OpenSearchClient (e.g., with AWS SDK transport)
OpenSearchClient customClient = new OpenSearchClient(myCustomTransport);

// Bind it to the registry so it can be autowired
context.getRegistry().bind("myOpenSearchClient", customClient);
----

The component will automatically pick up the `OpenSearchClient` from the registry via autowiring.
When both a `RestClient` and an `OpenSearchClient` are available, the `OpenSearchClient` takes precedence.
