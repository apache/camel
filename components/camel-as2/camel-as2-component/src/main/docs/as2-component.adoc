The AS2 component provides transport of EDI messages using the HTTP transfer protocol
as specified in https://tools.ietf.org/html/rfc4130[RFC4130]. 

Maven users will need to add the following dependency to their pom.xml
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-as2</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

as2://apiName/methodName
----

* client
* server

Several `as2://server/listen` consumers can share a `serverPortNumber`, each with its own `requestUriPattern`. Each
consumer applies its own keys and certificates and its own asynchronous MDN settings (`mdnUserName`, `mdnPassword`,
`mdnAccessToken` and `asyncMdnAllowedHosts`) to the messages received on its own pattern.

The settings of the shared server connection still come from the first endpoint created on the port:
`sslContextParameters` and `sslContext` (used for the TLS listener),
`mdnMessageTemplate`, `server`, `serverFqdn` and `as2Version`. They are per port, not per consumer.

=== Delivering asynchronous MDNs

When a received message asks for an asynchronous MDN, the `as2://server/listen` consumer delivers the MDN to the
address that the sender gave in the `Receipt-Delivery-Option` header. When `asyncMdnAllowedHosts` is set, the MDN is
delivered only to an address on the list, and the `mdnUserName`, `mdnPassword` and `mdnAccessToken` credentials are
attached only for such an address. Each entry of the list is a host with an optional port:

* a bare host, such as `partner.example`, matches only the default port for the scheme (80 for `http`, 443 for
`https`);
* a host and a port, such as `partner.example:8443`, match that port only;
* an IPv6 literal is written in square brackets, as in a URL: `[::1]` matches the default port, and `[::1]:8443`
matches port 8443. Without the brackets, `::1:8443` is read as another IPv6 address, not as `::1` with a port.
