= SWIFT MX DataFormat
:doctitle: SWIFT MX
:shortname: swiftMx
:artifactid: camel-swift
:description: Encode and decode SWIFT MX messages
:since: 3.20
:supportlevel: Stable
:tabs-sync-option:

*Since Camel {since}*

The SWIFT MX data format is used to encode and decode SWIFT MX messages. The data format leverages the library https://github.com/prowide/prowide-iso20022[Prowide ISO 20022] to encode and decode SWIFT MX messages.

== Options

In Spring DSL, you configure the data format using this tag:

._XML-only: Spring XML data format configuration_
[source,xml]
----
<camelContext>
    <dataFormats>
        <swiftMx id="swiftInJson" writeInJson="true"/>
    </dataFormats>
    ...
</camelContext>
----

Then you can use it later by its reference:

[tabs]
====
Java::
+
[source,java]
----
from("direct:startEncode")
    .marshal("swiftInJson")
    .to("mock:result");
----

XML::
+
[source,xml]
----
<route>
     <from uri="direct:startEncode" />
     <marshal>
       <custom ref="swiftInJson" />
     </marshal>
     <to uri="mock:result" />
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:startEncode
      steps:
        - marshal:
            custom:
              ref: swiftInJson
        - to:
            uri: mock:result
----
====

Most of the time, you won't need to declare the data format if you use
the default options. In that case, you can declare the data format
inline as shown below:

[tabs]
====
Java::
+
[source,java]
----
from("direct:startEncode")
    .marshal().swiftMx()
    .to("mock:result");
----

XML::
+
[source,xml]
----
<route>
    <from uri="direct:startEncode" />
    <marshal>
        <swiftMx />
    </marshal>
    <to uri="mock:result" />
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:startEncode
      steps:
        - marshal:
            swiftMx: {}
        - to:
            uri: mock:result
----
====

== Marshal

In this example, we marshal the messages read from a JMS queue in SWIFT format before storing the result into a file.
The body must be a Prowide MX object, such as an `MxPacs00800108`, as unmarshal gives: it is not converted, so an MX
message as text fails.

[tabs]
====
Java::
+
[source,java]
----
from("jms://myqueue")
    .marshal().swiftMx()
    .to("file://data.bin");
----

XML::
+
[source,xml]
----
<route>
  <from uri="jms://myqueue"/>
  <marshal>
    <swiftMx/>
  </marshal>
  <to uri="file://data.bin"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: jms://myqueue
      steps:
        - marshal:
            swiftMx: {}
        - to:
            uri: file://data.bin
----
====

== Unmarshal

The unmarshaller converts the input data into the concrete class of type `com.prowidesoftware.swift.model.mx.AbstractMX` that best matches with the content of the message.

In this example, we unmarshal the content of a file to get SWIFT MX
objects before processing them with the `newOrder` processor.

[tabs]
====
Java::
+
[source,java]
----
from("file://data.bin")
    .unmarshal().swiftMx()
    .process("newOrder");
----

XML::
+
[source,xml]
----
<route>
  <from uri="file://data.bin"/>
  <unmarshal>
    <swiftMx/>
  </unmarshal>
  <to uri="bean:newOrder"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: file://data.bin
      steps:
        - unmarshal:
            swiftMx: {}
        - to:
            uri: bean:newOrder
----
====

== Translating between MT and MX

The SWIFT MX and xref:swiftMt-dataformat.adoc[SWIFT MT] data formats read and write messages, but they do not translate
one format into the other. They also do not validate messages against SWIFT network rules or usage guidelines such as CBPR+ or SEPA.

To convert a message, such as an MT103 into a pacs.008, unmarshal it with SWIFT MT, map the fields to an ISO 20022 model class
such as `MxPacs00800108` in your own bean or processor, and marshal the result with SWIFT MX.
The other direction works the same way, starting with SWIFT MX.

Translation that follows the official SWIFT mapping rules is outside the scope of Camel. Use a dedicated translation product or service for that.

== Dependencies

To use SWIFT MX in your Camel routes, you need to add a dependency on
*camel-swift* which implements this data format.

If you use Maven, you can add the following to your pom.xml:

[source,xml]
----
<dependency>
  <groupId>org.apache.camel</groupId>
  <artifactId>camel-swift</artifactId>
  <version>x.x.x</version>  <!-- use the same version as your Camel core version -->
</dependency>
----
