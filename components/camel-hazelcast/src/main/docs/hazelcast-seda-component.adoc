The http://www.hazelcast.com/[Hazelcast] SEDA component is one of Camel Hazelcast Components which allows you to access Hazelcast BlockingQueue.
SEDA component differs from the rest components provided. It implements a work-queue in order to support asynchronous SEDA architectures, similar to the core "SEDA" component.

== SEDA producer – to(“hazelcast-seda:foo”)

The SEDA producer provides no operations. You only send data to the
specified queue.

[tabs]
====

Java DSL::
+
[source,java]
--------------------------
from("direct:foo")
.to("hazelcast-seda:foo");
--------------------------

Spring XML::
+
[source,xml]
----------------------------------
<route>
   <from uri="direct:start" />
   <to uri="hazelcast-seda:foo" />
</route>
----------------------------------

====

== SEDA consumer – from(“hazelcast-seda:foo”)

The SEDA consumer provides no operations. You only retrieve data from
the specified queue.

[tabs]
====

Java DSL::
+
[source,java]
--------------------------
from("hazelcast-seda:foo")
.to("mock:result");
--------------------------

Spring XML::
+
[source,xml]
-----------------------------------
<route>
  <from uri="hazelcast-seda:foo" />
  <to uri="mock:result" />
</route>
-----------------------------------

====

== Transferring the whole exchange

By default only the message body goes on the queue. With `transferExchange=true` the producer puts the whole exchange
on the queue: the body, and the headers and exchange properties whose values are text, numbers, booleans or dates. A
consumer with `transferExchange=true` restores them. A consumer without the option takes only the body of such an
exchange: set `transferExchange=true` on both endpoints to keep the headers and exchange properties.

[source,yaml]
----
- route:
    from:
      uri: direct:foo
      steps:
        - to:
            uri: hazelcast-seda:foo
            parameters:
              transferExchange: true
- route:
    from:
      uri: hazelcast-seda:foo
      parameters:
        transferExchange: true
      steps:
        - to:
            uri: mock:result
----
