*{component-header}*

The FOP component allows you to render a message into different output
formats using http://xmlgraphics.apache.org/fop/index.html[Apache FOP].

NOTE: When running on JDK 25 or later, Apache FOP encounters a re-entrant XML parsing error due to an internal JDK change (https://issues.apache.org/jira/browse/FOP-3275[FOP-3275]).
To work around this, add `net.sf.saxon:Saxon-HE` to your classpath, which provides an alternative XSLT processor that is not affected by this issue.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
------------------------------------------------------------
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-fop</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
------------------------------------------------------------

== Usage

=== Output Formats

The primary output format is PDF, but other output
http://xmlgraphics.apache.org/fop/0.95/output.html[formats] are also
supported:

[width="100%",cols="10%,10%,80%",options="header",]
|=======================================================================
|name |outputFormat |description

|PDF |application/pdf |Portable Document Format

|PS |application/postscript |Adobe Postscript

|PCL |application/x-pcl |Printer Control Language

|PNG |image/png |PNG images

|JPEG |image/jpeg |JPEG images

|SVG |image/svg+xml |Scalable Vector Graphics

|XML |application/X-fop-areatree |Area tree representation

|MIF |application/mif |FrameMaker's MIF

|RTF |application/rtf |Rich Text Format

|TXT |text/plain |Text
|=======================================================================

The complete list of valid output formats can be found in the `MimeConstants.java` source file.

=== Configuration file

The location of a configuration file with the following
http://xmlgraphics.apache.org/fop/1.0/configuration.html[structure].
The file is loaded from the classpath by
default. You can use `file:`, or `classpath:` as prefix to load the
resource from file or classpath. In previous releases, the file is always
loaded from the file system.

=== Message Operations

The `CamelFop.Render.*` headers set the metadata and rendering options of each document, and the `CamelFop.Encrypt.*`
headers encrypt a PDF document. The option names are matched case-insensitively (`CamelFop.Render.Creator` sets the
creator too). The values are used as given and converted to the type of the option, so a route that needs a property
placeholder or a bean in such a value resolves it before the `fop` endpoint, for example with the
xref:languages:simple-language.adoc[Simple] language. Other names are ignored, and a WARN is logged. Other FOP user
agent settings are set in the <<Configuration file>> or on a custom `FopFactory`.

[width="100%",cols="10%,10%,80%",options="header",]
|=======================================================================
|name |default value |description

|`CamelFop.Output.Format` |  | Overrides the output format for that message

|`CamelFop.Encrypt.userPassword` |  | PDF user password

|`CamelFop.Encrypt.ownerPassword` |  | PDF owner password

|`CamelFop.Encrypt.allowPrint` | `true` |Allows printing the PDF

|`CamelFop.Encrypt.allowPrintHq` | `true` |Allows printing the PDF in high quality

|`CamelFop.Encrypt.allowCopyContent` |`true` |Allows copying content of the PDF

|`CamelFop.Encrypt.allowEditContent` |`true` |Allows editing content of the PDF

|`CamelFop.Encrypt.allowEditAnnotations` |`true` |Allows editing annotation of the PDF

|`CamelFop.Encrypt.allowFillInForms` |`true` |Allows filling in the forms of the PDF

|`CamelFop.Encrypt.allowAccessContent` |`true` |Allows extracting content of the PDF for accessibility

|`CamelFop.Encrypt.allowAssembleDocument` |`true` |Allows assembling the PDF (inserting, rotating and deleting pages)

|`CamelFop.Encrypt.encryptMetadata` |`true` |Whether the metadata of the PDF is encrypted

|`CamelFop.Encrypt.encryptionLengthInBits` |`128` |The length of the encryption key in bits

|`CamelFop.Render.producer` |Apache FOP |Metadata element for the system/software that produces the document

|`CamelFop.Render.creator` |  | Metadata element for the user that created the document

|`CamelFop.Render.creationDate` |  | Creation Date, as a `java.util.Date`

|`CamelFop.Render.author` |  | Author of the content of the document

|`CamelFop.Render.title` |  | Title of the document

|`CamelFop.Render.subject` |  | Subject of the document

|`CamelFop.Render.keywords` |  | Set of keywords applicable to this document

|`CamelFop.Render.targetResolution` |  |The target resolution in dpi (the FOP configuration sets the default)

|`CamelFop.Render.accessibility` |  |Whether the accessibility features (tagged PDF) are enabled (the FOP configuration sets the default)

|`CamelFop.Render.pdfUAEnabled` |  |Whether the document conforms to PDF/UA

|`CamelFop.Render.keepEmptyTags` |  |Whether empty tags are kept in the structure tree of a tagged PDF (the FOP configuration sets the default)

|`CamelFop.Render.locatorEnabled` |`true` |Whether the location of an FO element is kept for error messages

|`CamelFop.Render.conserveMemoryPolicy` |  |Whether FOP writes pages to a temporary file to save memory
|=======================================================================

=== Example

Below is an example route that renders PDFs from XML data and XSLT
template and saves the PDF files in the target folder:

[source,java]
---------------------------------
from("file:source/data/xml")
    .to("xslt:xslt/template.xsl")
    .to("fop:application/pdf")
    .to("file:target/data");
---------------------------------
