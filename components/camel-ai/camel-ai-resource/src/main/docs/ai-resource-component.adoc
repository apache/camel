The AI Resource component exposes Camel routes as read-only resources that an AI client can fetch by uri.
Where xref:ai-tool-component.adoc[AI Tool] models an action the model decides to invoke, a resource models
content the client reads: a configuration file, a report on S3, a document on an FTP server.

Today the only adapter reading this registry is xref:others:mcp-server.adoc[camel-mcp-server], which publishes the
selected resources over MCP `resources/list` and `resources/read`.

Maven users will need to add the following dependency to their `pom.xml`
for this component:

[source,xml]
----
<dependency>
    <groupId>org.apache.camel</groupId>
    <artifactId>camel-ai-resource</artifactId>
    <version>x.x.x</version>
    <!-- use the same version as your Camel core version -->
</dependency>
----

== URI format

----
ai-resource:resourceName?resourceUri=uri[&options]
----

Where *resourceName* is the human-readable label shown in resource listings, and *resourceUri* is the address
clients use to read the resource. The uri must be unique within the CamelContext. For a family of resources, use
`uriTemplate` instead of `resourceUri`; the two options are mutually exclusive.

A `uriTemplate` follows RFC 6570 level 1: each variable must occupy an entire path segment, for example
`crm://customers/{id}`. Variables do not match across `/` separators. A concrete variable must use
RFC 3986 `pchar` characters (including well-formed percent-encoded octets); raw query/fragment
characters, controls, malformed percent escapes, and `.` or `..` dot segments do not match.
Fixed resources take precedence over a matching template when the same concrete URI is read.
Tagged templates in one CamelContext must not overlap, even when they belong to different tags;
a conflicting route fails startup rather than depending on registration order. A fixed
`resourceUri` must not contain raw `{` or `}`; use `uriTemplate` for variable paths.

== Usage

A resource read carries no arguments: the route is invoked with an empty exchange and its message body is the
content returned to the client. Retrieval therefore uses whatever Camel already offers for reading on demand: a
producer with a read operation (`aws2-s3` with `operation=getObject`), or `pollEnrich` for the polling components
(`file`, `ftp`, `sftp`), whose producers write rather than read.

Always give `pollEnrich` an explicit `timeout` - it is a parameter of the EIP, not an endpoint option. It
defaults to `-1`, which waits until a message is available and
parks the route thread for good when the file is not there. The client is still answered - the read returns a
timeout error after `camel.server.mcp-resource-timeout` - but the route stays blocked. Note also that `noop=true`
implies `idempotent=true`, so `idempotent=false` is what keeps the same file readable on every request.

=== Textual resource

[tabs]
====
Java::
+
[source,java]
----
from("ai-resource:app_config"
    + "?resourceUri=camel:///config/app.json"
    + "&tags=crm"
    + "&description=Current application configuration"
    + "&mimeType=application/json")
    .pollEnrich("file:config?fileName=app.json&noop=true&idempotent=false", 5000);
----

XML::
+
[source,xml]
----
<route>
  <from uri="ai-resource:app_config?resourceUri=camel:///config/app.json&amp;tags=crm&amp;description=Current application configuration&amp;mimeType=application/json"/>
  <pollEnrich timeout="5000">
    <constant>file:config?fileName=app.json&amp;noop=true&amp;idempotent=false</constant>
  </pollEnrich>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: ai-resource:app_config
      parameters:
        resourceUri: "camel:///config/app.json"
        tags: crm
        description: "Current application configuration"
        mimeType: application/json
      steps:
        - pollEnrich:
            timeout: 5000
            expression:
              constant:
                expression: "file:config?fileName=app.json&noop=true&idempotent=false"
----
====

=== Templated resource

Use `uriTemplate` when one route serves a family of client-addressable resources. The example below exposes
`crm://customers/{id}` and makes the concrete URI and captured variable available to the route:

[source,java]
----
from("ai-resource:customer?uriTemplate=crm://customers/{id}&tags=crm")
    .process(exchange -> {
        String customerId = exchange.getMessage().getHeader(
            "CamelAiResourceTemplateVariable.id", String.class);
        String requestedUri = exchange.getMessage().getHeader("CamelAiResourceUri", String.class);
        // Validate customerId against the application's identifier rules before using it.
        exchange.getMessage().setBody("Customer " + customerId + " requested as " + requestedUri);
    });
----

For each template read, Camel sets `CamelAiResourceUri` to the concrete URI sent by the client and sets one header
per variable using the prefix `CamelAiResourceTemplateVariable.` followed by the variable name. Variable values are
passed as raw strings; percent-encoding is retained. These values are untrusted client input. Validate them against
an allowlist or strict format before using them to build file paths, database queries or downstream URIs. Do not treat
them as Camel property placeholders or evaluate them as expressions.

=== Binary resource

The `mimeType` decides how the route body is read. Types denoting text, such as any `text` subtype,
`application/json`, and any subtype ending in `json`, `xml` or `yaml`, are converted to a string. Every other
type is read as `byte[]` and delivered to the client as a binary blob.

[source,java]
----
from("ai-resource:latest_report"
    + "?resourceUri=s3://reports/latest.pdf"
    + "&tags=crm"
    + "&description=Latest sales report"
    + "&mimeType=application/pdf")
    .to("aws2-s3://reports?keyName=latest.pdf&operation=getObject");
----

== Tags and exposure

Tags group resources so that an adapter can select which ones to expose. A resource without tags goes into a
default pool that `camel-mcp-server` never exposes: crossing the boundary to a remote client is an explicit
per-route opt-in. See the xref:others:mcp-server.adoc[MCP server] documentation for how the tag patterns are
configured.

== Lifecycle

A resource is registered when its route starts or resumes and deregistered when the route stops or suspends.
Adapters that support it turn those events into `notifications/resources/list_changed`, so clients see the
resource list follow the routes.
