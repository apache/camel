*Since Camel {since}*

Camel supports https://github.com/datasonnet/datasonnet-mapper[DataSonnet] transformations to allow an
xref:manual::expression.adoc[Expression] or xref:manual::predicate.adoc[Predicate] to be
used in the xref:manual::dsl.adoc[DSL].

For example, you could use DataSonnet to create a
Predicate in a xref:eips:filter-eip.adoc[Message
Filter] or as an Expression for a
xref:eips:recipientList-eip.adoc[Recipient List].

To use a DataSonnet expression, use the following Java code:

._Java-only: creating a DataSonnet expression_
[source,java]
----
datasonnet("someDSExpression");
----

== Usage

=== Setting a result type

The xref:datasonnet-language.adoc[DataSonnet] expression will return a `com.datasonnet.document.Document` by default. The
document preserves the content type metadata along with the contents of the transformation result. In predicates,
however, the Document will be automatically unwrapped and the boolean content will be returned. Similarly, any time you
want the content in a specific result type like a String. To do this, you have to instruct the
xref:datasonnet-language.adoc[DataSonnet] which result type to return.

[tabs]
====
Java::
+
[source,java]
----
from("direct:start")
    .setBody(datasonnet("body.foo", String.class))
    .to("mock:result");
----

XML::
+
[source,xml]
----
<route>
  <from uri="direct:start"/>
  <setBody>
    <datasonnet resultType="java.lang.String">body.foo</datasonnet>
  </setBody>
  <to uri="mock:result"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:start
      steps:
        - setBody:
            expression:
              datasonnet:
                expression: body.foo
                resultType: java.lang.String
        - to:
            uri: mock:result
----
====

In XML and YAML DSL, `resultType` is the fully qualified class name.

If the expression results in an array, or an object, you can instruct the expression to return you `List.class`
or `Map.class`, respectively. However, you must also set the output media type to `application/x-java-object`.

NOTE: The default `Document` object is useful in situations where there are intermediate transformation steps, and so
retaining the content metadata through a route execution is valuable.

=== Specifying Media Types

Traditionally, the input and output media types are specified through the
https://datasonnet.s3-us-west-2.amazonaws.com/docs-ci/primary/master/datasonnet/1.0-SNAPSHOT/headers.html[DataSonnet Header].
The xref:datasonnet-language.adoc[DataSonnet] expression provides convenience options for specifying the body and output
media types without the need for a Header, this is useful if the transformation is a one-liner, for example.

The DataSonnet expression will look for a body media type in the following order:

1. If the body is a `Document` it will use the metadata in the object
2. If the bodyMediaType parameter was provided in the DSL, it will use its value
3. A `CamelDatasonnetBodyMediaType` exchange property
4. A `Content-Type` message header
5. The DataSonnet Header payload media type directive
6. `application/x-java-object`

And for output media type:

1. If the outputMediaType parameter was provided in the DSL, it will use its value
2. A "CamelDatasonnetOutputMediaType" exchange property
3. A "CamelDatasonnetOutputMediaType" message header
4. The DataSonnet Header output media type directive
5. `application/x-java-object`

=== Camel Standard Library (`camel.libsonnet`)

Camel ships a standard library of helper functions that can be imported in any DataSonnet script:

[source,datasonnet]
----
local c = import 'camel.libsonnet';
{
  total: c.sumBy(body.items, function(i) i.price * i.qty),
  names: c.join(std.map(function(i) i.name, body.items), ', '),
  topItem: c.first(c.sortBy(body.items, function(i) -i.price))
}
----

=== Loading script from external resource

You can externalize the script and have Apache Camel load it from a resource
such as `"classpath:"`, `"file:"`, or `"http:"`. +
This is done using the following syntax: `"resource:scheme:location"`,
e.g., to refer to a file on the classpath you can do:

._Java-only: loading a DataSonnet script from an external resource_
[source,java]
----
.setHeader("myHeader").datasonnet("resource:classpath:mydatasonnet.ds");
----

== Examples

Here is a simple example using a DataSonnet expression as a predicate in a Message Filter:

[tabs]
====
Java::
+
[source,java]
----
// let's route if a line item is over $100
from("queue:foo")
    .filter(datasonnet("ds.arrays.firstWith(body.lineItems, function(item) item > 100) != null"))
    .to("queue:bar");
----

XML::
+
[source,xml]
----
<route>
    <from uri="queue:foo"/>
    <filter>
        <datasonnet>ds.arrays.firstWith(body.lineItems, function(item) item > 100) != null</datasonnet>
        <to uri="queue:bar"/>
    </filter>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: queue:foo
      steps:
        - filter:
            expression:
              datasonnet:
                expression: "ds.arrays.firstWith(body.lineItems, function(item) item > 100) != null"
            steps:
              - to:
                  uri: queue:bar
----
====


Here is an example of a simple DataSonnet expression as a transformation EIP. This example will transform an XML body with
`lineItems` into JSON while filtering out lines that are under 100.

[tabs]
====
Java::
+
[source,java]
----
from("queue:foo")
    .transform(datasonnet("ds.filter(body.lineItems, function(item) item > 100)", String.class, "application/xml", "application/json"))
    .to("queue:bar");
----

XML::
+
[source,xml]
----
<route>
    <from uri="queue:foo"/>
    <filter>
        <datasonnet bodyMediaType="application/xml" outputMediaType="application/json" resultType="java.lang.String" >
            ds.filter(body.lineItems, function(item) item > 100)
        </datasonnet>
        <to uri="queue:bar"/>
    </filter>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: queue:foo
      steps:
        - transform:
            expression:
              datasonnet:
                expression: "ds.filter(body.lineItems, function(item) item > 100)"
                resultType: java.lang.String
                bodyMediaType: application/xml
                outputMediaType: application/json
        - to:
            uri: queue:bar
----
====


== DataWeave Support

Camel can execute DataWeave (`.dwl`) scripts directly by auto-detecting and transpiling them to DataSonnet at load time.
No extra configuration is needed -- just reference a `.dwl` resource and Camel handles the conversion automatically.

=== Auto-detection

DataWeave scripts are detected in two ways:

- **By file extension**: any resource ending in `.dwl` (e.g., `resource:classpath:transform.dwl`)
- **By content**: inline expressions starting with the `%dw` header

Once detected, the script is transpiled to DataSonnet and executed via the datasonnet-mapper runtime.
The conversion happens once at route initialization, so there is no runtime overhead.

=== Example

Given a DataWeave file `transform.dwl` on the classpath:

[source,dataweave]
----
%dw 2.0
output application/json
---
{
    orderId: payload.order_id,
    customer: payload.customer.first_name ++ " " ++ payload.customer.last_name,
    total: payload.items map ((item) -> item.price * item.qty)
                         reduce ((item, acc = 0) -> acc + item)
}
----

You can use it directly in a route:

[tabs]
====
Java::
+
[source,java]
----
from("direct:in")
    .transform(datasonnet("resource:classpath:transform.dwl", String.class))
    .to("mock:result");
----

XML::
+
[source,xml]
----
<route>
    <from uri="direct:in"/>
    <transform>
        <datasonnet resultType="java.lang.String">resource:classpath:transform.dwl</datasonnet>
    </transform>
    <to uri="mock:result"/>
</route>
----

YAML::
+
[source,yaml]
----
- route:
    from:
      uri: direct:in
      steps:
        - transform:
            expression:
              datasonnet:
                expression: "resource:classpath:transform.dwl"
                resultType: java.lang.String
        - to:
            uri: mock:result
----
====

=== CLI Transpiler

You can also convert DataWeave scripts ahead of time using the Camel CLI:

[source,bash]
----
camel transform dataweave -e "payload.name ++ ' ' ++ payload.surname"
camel transform dataweave --input my-transform.dwl --output my-transform.ds
camel transform dataweave --input src/main/resources/dwl/ --output src/main/resources/ds/
----

=== How DataWeave is converted

The converted script keeps the DataWeave semantics, which differ from plain Jsonnet in important ways. For example, in
DataWeave a missing field, an index out of range or a selector on `null` gives `null`, a field selector on an array
selects the field of every element (`payload.items.price`), and most functions accept `null`. The converted script uses
the `dataweave.libsonnet` library of camel-datasonnet for these semantics (imported as `dw`), DataSonnet's `ds` library,
and the `cml` functions above.

The conversion either produces a script that gives the same result as the DataWeave script, or fails:

- Invalid DataWeave fails with a `DataWeaveConversionException` that reports the line and column.
- A construct that cannot be converted, and any function or variable the converter does not know, makes the route fail
  to start with a `DataWeaveConversionException`, instead of running a script that gives a different result.
  The CLI transpiler emits such constructs as a `TODO` comment and `null`, and reports how many need manual review.

=== Supported Constructs

- *Header*: `%dw`, `output` (JSON, XML, CSV, Java and text; for JSON the writer properties `skipNullOn`, `indent` and
  `encoding`), `input`, `import` of the `dw::core` modules, `var` and `fun` declarations (also with default parameters,
  recursive and calling each other), and `type` declarations (ignored).
- *Selectors*: `.field`, `."quoted field"`, `[index]` (negative from the end), `[from to to]`, `["key"]`, `.*field`,
  `..field`, `.@attribute`, `field?` and `[?(condition)]`.
- *Mule variables and attributes*: `payload` is the message body, `vars.name` (or `vars["name"]`) an exchange variable,
  and `attributes.headers`, `attributes.queryParams` and `attributes.uriParams` message headers. `attributes.method`,
  `requestPath`, `requestUri`, `queryString`, `statusCode` and `reasonPhrase` are the corresponding Camel HTTP headers.
- *Operators*, with the DataWeave precedence: arithmetic, comparison, `~=`, `and`, `or`, `not`, `++`, `--`, removing a
  key with `-`, `default`, `if`/`else`, `unless`/`else`, `match` (literal, `is Type`, `matches /regex/`, `if` guards
  and `else` cases), `do` blocks and `using`.
- *Functions* in prefix and infix form (`upper(x)`, `xs map f`), with lambdas `(item, index) -> ...`, the `$`, `$$` and
  `$$$` shorthand, and references to functions: `map`, `filter`, `reduce`, `flatMap`, `flatten`, `distinctBy`,
  `groupBy`, `orderBy`, `mapObject`, `filterObject`, `pluck`, `keysOf`, `namesOf`, `valuesOf`, `entriesOf`, `zip`,
  `unzip`, `sizeOf`, `isEmpty`, `isBlank`, `sum`, `avg`, `min`, `max`, `maxBy`, `minBy`, `then`, `to`, `upper`, `lower`,
  `trim`, `contains`, `startsWith`, `endsWith`, `splitBy`, `joinBy`, `replace ... with`, `matches`, `scan`, `find`,
  `abs`, `ceil`, `floor`, `round`, `sqrt`, `pow`, `mod`, `isEven`, `isOdd`, `isInteger`, `isDecimal`, `typeOf`, `now`,
  `uuid`, `p`, `log`, `fail`, `read` and `write`, and of the `dw::core` modules `camelize`, `capitalize`, `dasherize`,
  `underscore`, `pluralize`, `singularize`, `leftPad`, `rightPad`, `substringBefore`, `substringAfter` (and the other
  `Strings` functions), `take`, `drop`, `splitAt`, `divideBy`, `indexOf`, `countBy`, `sumBy`, `every`, `some`,
  `partition`, `firstWith` and `mergeWith`.
- *Objects*: dynamic keys `(key): value`, conditional fields `(key: value) if condition`, and object spread
  `{ (expression) }` of an object or an array of objects.
- *Strings*: interpolation (`"Hello $(expression)"`, `"Hello $name"` and `$` of a lambda), and regular expressions
  `/.../` in `replace` (also with a function of the matched groups: `replace /(\d+)/ with ($[1] ++ "!")`), `contains`,
  `splitBy`, `matches`, `scan` and `find`.
- *Type coercion*: `as String`, `as Number`, `as Boolean`, `as String {format: ...}` of numbers and dates,
  `as Date`, `as DateTime`, `as LocalDateTime`, `as Time` and `as LocalTime` (with or without `format`), date literals
  such as `|2020-01-31|`, date arithmetic with periods such as `|P1D|`, and the parts of a date such as `.year`.
  Dates and times are ISO-8601 strings in the converted script; as in DataWeave, a date coerced with a format is
  written in that format. Numbers and dates are formatted in the default locale (as DataWeave does), unless the
  coercion has a `locale` property.

The expected output of the DataWeave scripts in the tests of the conversion is verified with the DataWeave CLI.

These constructs are not converted (the conversion fails): the `update` operator, `try` (`dw::Runtime`), overloaded
functions, custom modules, `as` with a custom type, XML namespaces, XML attributes in the output, and writer properties
other than the ones listed above. The XML support is limited: an element with text is read as its text (as in
DataWeave), but the attributes of such an element are only kept when they are selected directly (`payload.order.@id`)
or in a lambda (`payload.orders.*order map $.@id`).

== Dependencies

To use scripting languages in your camel routes, you need to add a
dependency on *camel-datasonnet*.

If you use Maven you could just add the following to your `pom.xml`,
substituting the version number for the latest and greatest release (see
the download page for the latest versions).

[source,xml]
----
<dependency>
  <groupId>org.apache.camel</groupId>
  <artifactId>camel-datasonnet</artifactId>
  <version>x.x.x</version>
</dependency>
----
