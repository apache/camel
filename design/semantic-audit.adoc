= Semantic audit

CAMEL-25499 supplies the audit foundation. CAMEL-25618 builds the result, case and monitoring surfaces on
the shared AiEvent contract introduced by CAMEL-25408. CAMEL-25357 does not need a second recorder.
CAMEL-23369 can consume the events or the existing tracing observer hooks without an OpenTelemetry
dependency in camel-semantic.

== Assessment and provenance

Experts return typed assessments. Camel preserves the returned Boolean, choice, fractional score or
classification, along with execution state and supplied findings. The framework does not interpret
Boolean polarity, impose severity scales or infer a route action. New route-action capture, metadata,
filters and evidence workflows are removed. The preview SemanticAudit and SemanticAuditDecision APIs
are removed outright; the upgrade guide describes migration to automatic evaluation capture.
Persisted v1 decision records remain readable and exportable as legacy data.

Capture entry route and executing route separately, before invoking the provider. The existing routeId
field and query keep their entry-route meaning. No active route means no executing-route identity.
Copy both exchangeId and an existing valid Camel breadcrumbId without fabricating either. A breadcrumb
associates records; it does not prove causation or completeness.

== Shared events and retention

[source,mermaid]
----
flowchart LR
    R[Semantic runtime captures and freezes an assessment] --> E[Typed SemanticEvent with complete declared interpretation]
    E --> A[Audit recorder applies its own capture budget]
    I[Separately opted-in input snapshot] --> A
    A --> Q[Bounded queue and capability-aware audit sinks]
    E --> H[EventHelper.notifyAiEvent]
    H --> N[Registered EventNotifier listeners]
    N --> P[Expert or application event consumers]
----


The semantic runtime constructs an immutable occurrence snapshot once and passes a typed SemanticEvent
directly to the audit recorder and to EventHelper.notifyAiEvent. Starts, completed assessments and request
outcomes have distinct kinds. A cancellation observation does not replace eventual provider completion.
Each completed batch member has its own occurrence. Generic consumers select the kinds they understand.
Route-bound occurrences use SemanticExchangeEvent and AiEvent.ExchangeAiEvent for live correlation. Detached
calls do not fabricate an Exchange. Synchronous listeners can access the live body and headers, while getData
and JSON contain only frozen occurrence data. Consumers that enqueue or retain data must not retain the live
event or Exchange; the built-in recorder retains only frozen data.

The event carries the complete declared interpretation, including its original labels and meanings.
It is visible to all subscribed listeners. Event production does not truncate interpretation to an
audit-retention budget. Consumers that retain data own their payload, queue and storage budgets. EventHelper delivers synchronously and does not keep history.
Callbacks should perform short, bounded work; asynchronous consumers must define queue loss behavior.
Event toString methods contain identifiers and kind only because listener failures may log them.

The audit recorder is one such consumer. Before enqueueing, it projects the event into the bounded
SemanticAuditRecord format. Interpretation capture is all-or-nothing: 2048 code points in total,
32 alternatives/levels, 256 code points per label, and the existing bounded JSON depth/node rules.
Oversized interpretation is explicitly marked interpretationOmitted=audit_snapshot_limit. It remains
complete on the event delivered to other listeners. Queue closures retain the bounded record only.
Raw input is separately opt-in and attached privately to the audit copy after applying its capture and
redaction policy. Raw input is absent from the frozen event payload; an Exchange-aware listener can access
live input through getExchange regardless of audit capture settings.

Each sink declares supported extension groups through SemanticAuditCapabilities. Unknown groups are
removed for that destination, so older backends do not receive unrecognized v1 fields. Missing extension
support does not reject startup. Health responses expose destination and reader capabilities. Older
records without interpretation remain not recorded; current definitions never reconstruct historical meaning.

The audit queue and memory store default to 1000 entries each. Queue overflow drops the new record and
counts it; memory overflow evicts the oldest. External stores and logging infrastructure own their
retention and durability. Audit delivery is best effort and independent of management-listener filters.
SemanticObserver remains available for captureContext and detached tracing completion; its established
bounded projection and callback ordering remain compatible.

== Read-only access

The reader SPI has no evidence-specific limit on getAll. Explicit console callers limit requests to
1000 IDs and responses to 4 MiB, and use batches of at most 100 IDs for existing readers. Missing IDs
are separate from lookup failures. Query pages still permit at most 200 records; legacy stored evidence
lists still permit at most 100 references. Case retrieval has a five-second cooperative deadline between
backend operations. Backends must bound individual I/O calls and honor interruption.

Cases are scoped to the selected source and reader. Use a recorded breadcrumb, then exchange, invocation
or event identity, and retain supplied batch/request relationships. Additional reader filters are optional;
unsupported relationships and limited retrieval are visible. Retained history never proves completeness.
Case/bulk summaries exclude input. Explicit input-bearing export includes the untrusted-data warning.
Browsing, diagnostics and creating a playground draft must never invoke an expert.
